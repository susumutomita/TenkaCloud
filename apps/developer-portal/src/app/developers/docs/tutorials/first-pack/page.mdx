# First pack tutorial <MaturityBadge level="preview" />

Pack init, validation and immutable installation are authoring tools. Installing or activating a pack does not add its problems to this candidate's event catalog. The retained tenant-scoped activation command is a legacy local record, not a current hosting workflow.

Just want to run an existing pack? → [Use an existing pack](/developers/docs/operate/use-existing-pack/).

## Prerequisites

Run from the TenkaCloud repository root with Bun 1.3.11 and installed dependencies. Local-directory operations need no cloud credentials. Installing from Git contacts the given HTTPS repository.

<h2 id="scaffold">Scaffold a pack</h2>

```sh
make pack-init ARGS="./my-first-pack"
```

This writes a manifest, one starter problem, an artifact placeholder and README. The placeholder is not a completed runnable exercise.

<h2 id="validate">Validate the contract</h2>

```sh
make pack-validate ARGS="./my-first-pack"
```

Validation checks metadata, runtime declarations and files. It does not deploy, score or prove participant playability. Complete the problem and its own tests before making those claims.

<h2 id="install">Install and inspect locally</h2>

```sh
make pack-install ARGS="./my-first-pack"
make pack-list
bun run pack inspect com.example.starter@0.1.0
```

For a Git install use an HTTPS URL and full immutable 40-hex commit SHA. Keep source provenance and content digest. Do not use a moving branch as the revision.

<h2 id="runtime-boundary">Runtime boundary</h2>

There is no complete pack activate → event → deployment path in this candidate. Use its supported pinned core catalog to rehearse an event. Generic local catalog/workbench restoration is separate work. Do not run a deleted Lite launcher or invent a tenant to bridge this gap.

<h2 id="common-failures">Common failures and diagnostic codes</h2>

`PACK_DIR_MISSING`, `MANIFEST_INVALID`, duplicate IDs and missing artifacts need corrections in the pack, not a cloud deployment. See [validation errors](/developers/docs/reference/validation-errors/).

<h2 id="teardown">Remove a stored revision</h2>

```sh
bun run pack remove com.example.starter@0.1.0
```

Removal may refuse a retained activation/reference; inspect it first. Removing a pack is not exercise or cloud teardown. Historical SaaS/Lite and individual-practice instructions are available in the [pinned legacy source](https://github.com/susumutomita/TenkaCloud/tree/825415fcda5075ad723daf9e4514eac47d7b8bb9). Do not use them against this candidate or assume data migrates automatically.
