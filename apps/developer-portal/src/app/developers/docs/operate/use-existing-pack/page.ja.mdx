# 既存パックを使う <MaturityBadge level="preview" />

pack の作成、検証、不変な revision の保存は作問用の機能です。install や activate をしても、この candidate の大会カタログへ問題は追加されません。残っている tenant 単位の activate は旧版向けのローカル記録であり、現行の競技実行手順ではありません。

<h2 id="prerequisites">前提条件</h2>

信頼する pack のローカルディレクトリ、または HTTPS Git URL と完全な 40 桁 commit SHA を用意します。runtime、ファイル、provenance を確認してください。

<h2 id="install-the-pinned-git-revision">固定した revision を保存する</h2>

```sh
make pack-install ARGS="git <https-url> --commit <40-hex-commit-sha>"
make pack-list
bun run pack inspect <id@version>
```

リポジトリのルートで実行します。既定の保存先は `.tenkacloud/pack-store` です。Git install はネットワークを使います。ローカルディレクトリの検証や保存はリソースを配置しません。

<h2 id="verify-the-installed-revision">保存結果を確認する</h2>

取得元、解決済み commit、digest を確認します。install 成功は、任意コードの実行、endpoint の公開、クラウド作成の承認ではありません。

<h2 id="create-the-event">大会への接続は未対応</h2>

activate しても現在の大会選択欄へ pack の問題は追加されません。実装上の不足であり、実環境テストだけが未実施という状態ではありません。大会には対応する core catalog の問題を使い、pack の経路は Not run と記録します。[最初の pack](/developers/docs/tutorials/first-pack/)も参照してください。

SaaS/Lite と旧個人練習の手順は[固定した旧版](https://github.com/susumutomita/TenkaCloud/tree/825415fcda5075ad723daf9e4514eac47d7b8bb9)を参照してください。この candidate へ適用したり、データが自動移行されると考えたりしないでください。
