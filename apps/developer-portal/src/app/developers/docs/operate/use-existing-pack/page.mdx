# Use an existing pack <MaturityBadge level="preview" />

Pack init, validation and immutable installation are authoring tools. Installing or activating a pack does not add its problems to this candidate's event catalog. The retained tenant-scoped activation command is a legacy local record, not a current hosting workflow.

<h2 id="prerequisites">Prerequisites</h2>

Obtain a trusted local pack directory or HTTPS Git URL plus an immutable full 40-hex commit SHA. Review the declared runtime, files and provenance before installation.

<h2 id="install-the-pinned-git-revision">Install the pinned Git revision</h2>

```sh
make pack-install ARGS="git <https-url> --commit <40-hex-commit-sha>"
make pack-list
bun run pack inspect <id@version>
```

Run from the repository root. The default store is `.tenkacloud/pack-store`. Git install uses the network; local-directory validation and installation do not deploy anything.

<h2 id="verify-the-installed-revision">Verify the stored revision</h2>

Check the source, resolved commit and digest. Installation is not authorization to run arbitrary code, expose endpoints or create cloud resources.

<h2 id="create-the-event">Event integration is unavailable</h2>

Installed packs do not appear in the current event picker through activation. This is an implementation gap, not merely pending live batch verification. Use a supported core-catalog problem for an event and record the pack route as Not run. See [first pack tutorial](/developers/docs/tutorials/first-pack/).

Historical SaaS/Lite and individual-practice instructions are available in the [pinned legacy source](https://github.com/susumutomita/TenkaCloud/tree/825415fcda5075ad723daf9e4514eac47d7b8bb9). Do not use them against this candidate or assume data migrates automatically.
