# 起動と配置の境界 <MaturityBadge level="preview" />

未公開の統合 candidate の手順です。ローカルの大会・チーム運用は実装されていますが、クラウド基盤の配置や全カタログのプレイ確認が完了した公開版ではありません。

<h2 id="local-platform">ローカル基盤</h2>

`make local` は Bun のサーバーと二つの画面を起動し、SQLite へ状態を保存します。`make down` は所有するローカル環境を止め、大会データを保持します。旧 host target は別モードとして残しません。[はじめに](/developers/docs/getting-started/)で初期管理者、大会作成、参加者ログインを確認してください。

<h2 id="cloud-platform">クラウド基盤は未実装</h2>

`make deploy` と `make destroy` は、この版の Lambda/DynamoDB 配置と協調撤収 CLI を実行します。AWS 権限の事前確認が必要です。現在のクラウド問題は限定 CLI を使う hello-world です。非 AWS 問題のクラウド実行と Battle は未実装です。撤収ではアカウント、リージョン、所有対象を表示し、記録済み問題の撤収後に基盤を削除します。データは保持し、保持リソースには料金が発生する場合があります。復元した `infrastructure/templates/cloud-pipeline.yaml` は固定した旧版のソースを実行し、この版の CLI は実行しません。コンテナの build 成功は、配置済みや費用ゼロの証明ではありません。

<h2 id="exercise-deployment">問題環境の配置は別の操作</h2>

ローカル大会では所有情報付きの Docker Compose project と組み込み Battle を使います。AWS サービスの問題はクラウド開催専用で、確認した競技者アカウント、region、role、必須の ExternalId を使います。非 AWS 問題のクラウド実行には別の runner が必要です。問題リソースには費用が発生する場合があります。ローカル停止では、以前の AWS 対応版が作成した stack を削除しません。

<h2 id="legacy-installations">既存の旧版環境</h2>

SaaS/Lite と旧個人練習の手順は[固定した旧版](https://github.com/susumutomita/TenkaCloud/tree/825415fcda5075ad723daf9e4514eac47d7b8bb9)を参照してください。この candidate へ適用したり、データが自動移行されると考えたりしないでください。

SaaS tenant の rollout は旧版の契約です。改名した cloud pipeline は固定したソースに対する元の CodePipeline/CodeBuild 配置・撤収を維持します。既存環境の操作には、その環境を作成した正確な旧版を使ってください。
