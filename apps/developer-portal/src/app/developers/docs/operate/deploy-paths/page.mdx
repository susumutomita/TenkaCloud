# Launch and deployment boundaries <MaturityBadge level="preview" />

This documents the draft integration candidate. Local event/team operation is implemented; cloud platform deployment and complete catalog playability are not verified release claims.

<h2 id="local-platform">Local platform</h2>

`make local` runs the unified Bun server and two browser applications with persistent SQLite. `make down` stops owned local runtimes and preserves event data. The removed host target is not a second launch mode. See [getting started](/developers/docs/getting-started/) for bootstrap, event creation and participant login.

<h2 id="cloud-platform">Cloud platform: integration in progress</h2>

`make deploy` and `make destroy` execute the current Lambda/DynamoDB setup and coordinated teardown CLI. They require reviewed AWS permissions. The current cloud catalog supports hello-world with scoped CLI access; non-AWS execution and Battle remain incomplete. Destroy shows the account, region and owned targets, waits for recorded exercises to be removed, then removes hosting while retaining data. Retained resources can continue to incur charges. The preserved `infrastructure/templates/cloud-pipeline.yaml` runs fixed historical source refs, not this current CLI. A container build is not deployment evidence or a zero-cost promise.

<h2 id="exercise-deployment">Exercise deployment is separate</h2>

Local events use owned Docker Compose projects or native Battle execution. AWS-service problems are cloud-only and require reviewed competitor account/region/role configuration with ExternalId. Cloud execution of non-AWS exercises still needs a separate runner. Exercise resources can incur charges; stopping a local process does not remove resources created by an older AWS-enabled revision.

<h2 id="legacy-installations">Legacy installations</h2>

Historical SaaS/Lite and individual-practice instructions are available in the [pinned legacy source](https://github.com/susumutomita/TenkaCloud/tree/825415fcda5075ad723daf9e4514eac47d7b8bb9). Do not use them against this candidate or assume data migrates automatically.

SaaS tenant rollout remains historical. The renamed cloud pipeline preserves its original CodePipeline/CodeBuild deployment and cleanup for its pinned source refs. Use the exact legacy version that owns an existing deployment for its lifecycle operations.
