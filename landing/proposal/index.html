TenkaCloud ／ フィードバックパートナー募集1 / 11

OJT任せになっていないか

この4つに、
課題はありませんか。

  1. セキュリティ

    危ない設定に気づく目は、事故やレビューで指摘されて初めて身につく。

  2. クラウドのシステム構築

    設計から公開まで通しで作る経験は、担当になった人にしか回ってこない。

  3. インシデント発生時の避難訓練

    本番の障害は待ってくれないのに、慌てずに動く練習をする場がない。

  4. エンジニア間の交流のきっかけ

    チームや部署をまたいで、一緒に手を動かす機会が少ない。

どれも、その場に居合わせた人だけが覚えていきます。

OJT任せになっているもの2 / 11

TENKACLOUD でできること

その4つを、
チームで練習できる場にします。

セキュリティ

攻撃する側の目で確かめる。外から見えてはいけない物や、社員だけのはずのログイン画面を調べ、答え（Flag）を見つけて提出する。

クラウド構築

本物のクラウドで作り込む。チームごとに用意した環境を、公開してよい状態まで仕上げる。直した状態を定期的なチェックで採点する。

避難訓練

壊れた状態から始める。深夜のデプロイの翌朝にサービスが開かない。原因を突き止めて、時間内に戻す。

交流

部署をまたいだチームで競う。スコアボードで互いの進み具合が見え、終わったら採点の記録を見ながらふりかえる。

問題は公開カタログから選ぶか、自分たちのシステムや過去の障害を題材に書けます。主催者は1つの画面で大会・チーム・問題・ヒント・採点を管理します。

なぜパートナーを探しているか

作り手だけでは、
分からないことがあります。

  1. 4つのうち、どれから練習にすると効くか。
  2. 問題の難しさは、参加者に合っているか。
  3. 開催者の準備は、どこで止まるか。
  4. 社内ネットワークの条件で、参加者がつながるか。

答えは、実際のチームで開催してみないと出てきません。

なぜ募集するか6 / 11

パートナーになると

一緒に1回、開催してみませんか。

私たちがすること

  • 準備から当日まで一緒に入る。問題選び、開催 PC の準備、リハーサル、当日の進行。
  • 出てきた不具合や要望を優先して検討する。直したものは OSS として公開します。
  • 問題づくりの相談に乗る。自分たちのシステムに近い題材から作れます。

お願いしたいこと

  • 4つのどれかを題材に、実際のチームで1回開催する。2チームほどの小さな回で十分です。
  • 終わったあと、30分のふりかえりに付き合う。採点の記録を見ながら話します。
  • 気づいたことを、良くも悪くもそのまま伝える。GitHub Issue でもメールでも。

事例として紹介してよいかは、開催のあとで相談させてください。OSS なので、終わったあとも自分たちで開催を続けられます。
