# 常設ゲームから実践演習へ

1〜3 分で 1 つの判断を試す。開いたらプレーし、間違えた場所で短い理由を知り、すぐ別の判断を試す。長い説明の事前受講は置きません。詳細は任意、所要時間・定着効果は保証しません。

| 段階 | 試す判断 | 体験の候補 | 状態 |
| --- | --- | --- | --- |
| 日常を守る | 依頼の見た目と、危険につながる相違点を区別 | 2つのメールを見比べる間違いさがし | 第1弾のみローカル実装、未公開 |
| 日常を守る・続き | 使い回し、パスキー、二段階と多要素、回復手段を区別 | 1プレーで一判断の短いゲーム | 構想のみ |
| 開発の基礎 | 必要な通信や権限と不要な公開を区別 | WebとDBの2層通信パズル、状況に応じたWordPress対処 | 構想のみ |
| 暗号の基礎 | 共通鍵／公開鍵／電子署名の役割を区別 | 短い暗号バトルからTLSと証明書チェイン・中間証明書へ | 構想のみ |
| TenkaCloud実践 | 条件を読み、実環境で操作し結果を確かめる | 本体のChallenge/Battleへ接続 | 本体の提供範囲・実行条件に従う |

二段階は手順の段階数、多要素は異なる種類の要素の組合せで、同じ意味ではありません。パスキーの性質や回復は具体的な方式・端末条件を示して扱います。
運用課題では前提・脅威・制約・目標を明示し、複数の妥当な手段があれば許容します。WordPress 等で特定の設定を状況に関係なく唯一の正解とはしません。

暗号段階はまだ教材化しません。公開鍵暗号で通信データ全部を暗号化する、証明書があるのでサイトの内容は安全、といった説明にはしません。
TLS1.3 ではハンドシェイクの鍵交換・認証と通信データの保護を区別します。証明書チェインでは中間証明書を含む署名のつながりと信頼点の検証を扱い、名前・有効期間等の確認も必要です。現在の呼称は TLS です。旧 SSL を同義の現行プロトコルとして教えません。

## 今回の範囲

`landing/mail-detective/` のメールゲームだけ。4 組の架空ケースから 2 組を毎回抽選し、危険につながる差 3 個と正常な差 2 個を比較します。答えと判定はクライアントで閲覧できます。学習用で、秘密の採点や能力認定ではありません。登録・大会・AWS・Docker・外部 API・API キーは不要です。
既存の競技用第 1/2 問と第 3 問途中、LP の別 PR は保全。後続ゲーム、効果測定サービス、SNS 共有機能、公開は今回の実装範囲に含めません。
