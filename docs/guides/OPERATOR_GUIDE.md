# TenkaCloud 運営者ガイド

TenkaCloud で GameDay イベントを企画・運営するための手順書です。

## 前提条件

GameDay イベントを実施するには、以下の準備が必要です。

- TenkaCloud にテナントが登録済みであること
- AWS アカウントへのアクセス権があること（問題のデプロイに使用）
- 問題パッケージ（CloudFormation テンプレート）が用意されていること
- 管理者権限で Application Plane にログインできること

## イベントのセットアップ

### 1. イベントの作成

管理画面（`/admin/events`）からイベントを作成します。

1. 「新規イベント作成」をクリック
2. 以下の項目を入力する
   - イ��ント名（例:「2026 年度セキュリティ GameDay」）
   - イベントタイプ: `gameday` を選択
   - 開始日・終了日
   - 最大参加者数
3. 「作成」をクリック

イベントが作成されると、GameDay のゲーム状態が自動で初期化されます。

### 2. 問題の追加

管理画面のイベント詳細（`/admin/events/[eventId]/problems`）から問題を追加します。

1. イベント詳細ページの「問題」タブを開く
2. 「問題を追加」から、使用する問題パッケージを選択する
3. 各問題の脆弱性の種類と難易度を確認する

### 3. 問題の AWS デプロイ

問題を参加者の AWS 環境にデプロイします。

1. 問題詳細ページで「デプロイ」をクリック
2. デプロイ先の AWS リージョンを選択する
3. 「デプロイ実行」をクリック
4. CloudFormation スタックの作成完了を待つ

### 4. 攻撃カタログの生成

GameDay コントロールパネル（`/admin/gameday/[eventId]`）で攻撃カタログを生成します。

1. 「攻撃管理」タブを開く
2. 「攻撃カタログ生成」をクリック

12 種類の攻撃が自動で登録されます。攻撃の種類は以下の通りです。

**脆弱性悪用型（vulnerability）**

| 攻撃名 | 対象の脆弱性 |
|---|---|
| SQL Injection | SQL インジェクション |
| Remote Code Execution | バックドア |
| Password Rotation | ハードコードパスワード |
| SSRF Attack | SSRF |
| Leaked Credentials | 認証情報漏洩 |
| Backdoor | 隠しルート |
| Compromised Website | Web サイト改竄 |
| Data Exfiltration | データ漏洩 |
| Hacked Bucket | S3 バケット公開設定 |

**カオス型（chaos）**

| 攻撃名 | 内容 |
|---|---|
| HA/Resilience Attack | インフラ障害シミュレーション |
| EC2 System Status Check Failed | EC2 ステータスチェック障害 |
| MHCS | ヘルスチェック障害注入 |

すべての攻撃は購入コスト 3,000 ポイント、ダメージ 1,000 ポイント、報酬 1,000 ポイント、クールダウン 300 秒で統一されています。

## イベントの実施

### 事前チェックリスト

ゲーム開始前に以下を確認してください。

- [ ] チームが登録されている（「チーム管理」タブで確認）
- [ ] 各チームの Web サイト URL と API URL が設定されている
- [ ] 攻撃カタログが生成済みである（「攻撃管理」タブで確認）
- [ ] 問題が AWS にデプロイ済みである
- [ ] 参加者全員がログイン・チーム参加済みである

### ゲームの開始

1. GameDay コントロールパネル（`/admin/gameday/[eventId]`）を開く
2. 「ゲーム制御」タブでゲーム時間（分）を入力する（デフォルト: 60 分）
3. 「ゲーム開始」をクリック

ゲーム開始と同時に、登録済みの全チームに初期ポイント **10,000 ポイント** が付与されます。

### 監査（ヘルスチェック）の開始

ゲーム開始後、「監査制御」タブから監査プロセスを開始します。

1. 「監査開始」をクリック
2. 60 秒ごとに全チームの Web サイトと API のヘルスチェックが実行される

ヘルスチェックの結果はスコアに反映されます。

- 正常: +100 ポイント
- 異常（通常モード）: -100 ポイント
- 異常（高倍率モード）: -1,000 ポイント

### ゲーム中の監視

コントロールパネルは 10 秒ごとに自動更新されます。以下を監視できます。

- **ゲーム制御タブ**: ゲームの状態、経過時間、残り時間
- **チーム管理タブ**: 各チームのスコア、URL、ヘルス状態
- **攻撃管理タブ**: 全攻撃ログ（時間、攻撃者、防衛者、結果、ダメージ）
- **監査制御タブ**: 監査プロセスの稼働状態

### スコア重みの切り替え

ゲーム終盤など盛り上げたい場面で、スコアの倍率を変更できます。

1. 「ゲーム制御」タブの「スコア重み」トグルを ON にする
2. ヘルスチェックのペナルティが -100 から **-1,000** に変わる
3. 再度トグルすると通常モードに戻る

### ブラックアウトの活用

最終結果発表を盛り上げるため、リーダーボードを非表示にできます。

1. 「ゲーム制御」タブの「ブラックアウト」トグルを ON にする
2. 参加者のリーダーボード画面にスコアが表示されなくなる
3. 残り 30 分になると自動でブラックアウトが有効になる

### 妨害注入

管理者として特定のチームに直接攻撃できます。ゲームの展開を調整するために使用します。

1. 「妨害注入」タブを開く
2. 対象チームと攻撃の種類を選択する
3. 「妨害実行」をクリック

### ゲームの停止

1. 「ゲーム制御」タブの「ゲーム停止」をクリック
2. 設定時間を超過した場合は自動で停止される

## イベント終了後

### 最終結果の確認

1. ブラックアウトを解除する（有効な場合）
2. リーダーボードで最終順位を確認する
3. 攻撃ログで各チームの活動を振り返る

### AWS リソースのクリーンアップ

イベント終了後は、デプロイした AWS リソースを削除してください。

1. 管理画面の問題一覧（`/admin/problems`）を開く
2. デプロイ済みの問題ごとに「削除」を実行する
3. AWS コンソールで CloudFormation スタックが削除されたことを確認する

## トラブルシューティング

### チームが接続できない

- チームの Web サイト URL と API URL が正しく設定されているか確認する
- URL が HTTPS でアクセス可能であるか確認する
- ファイアウォールやセキュリティグループの設定を確認する

### 攻撃が機能しない

- 攻撃カタログが生成済みであるか確認する（「攻撃管理」タブ）
- ゲームが「稼働中」状態であるか確認する
- チームに攻撃購入に必要な 3,000 ポイント以上のスコアがあるか確認する

### スコアが更新されない

- ゲームが「稼働中」状態であるか確認する
- 監査プロセスが起動しているか確認する（「監査制御」タブ）
- ブラウザのコンソールでエラーが出ていないか確認する

### ヘルスチェックが失敗し続ける

- チームの URL が正しいか確認する
- 対象サービスが起動しているか確認する
- ヘルスチェックのタイムアウトは 10 秒であるため、レスポンスが遅い場合は改善を依頼する

### 監査プロセスが停止した

- 「監査制御」タブで「監査開始」を再度クリックする
- ゲームが終了している場合は監査を再開する必要はない

## ポイント経済の概要

運営者として把握すべきポイントの流れは以下の通りです。

| 項目 | ポイント |
|---|---|
| 初期ポイント | +10,000 |
| 攻撃購入 | -3,000 |
| 攻撃成功（攻撃者への報酬） | +1,000 |
| 攻撃被弾（防衛者へのダメージ） | -1,000 |
| 攻撃防御成功（防衛者への報酬） | +1,000 |
| 脆弱性修正 | +1,500 |
| ヘルスチェック正常 | +100 |
| ヘルスチェック異常（通常） | -100 |
| ヘルスチェック異常（高倍率） | -1,000 |
| ヒント購入 | -500 〜 -3,000 |
| 投票ボーナス（投票された側） | +5,000 |
