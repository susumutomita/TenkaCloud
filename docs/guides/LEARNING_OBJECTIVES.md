# TenkaCloud 学習目標

TenkaCloud GameDay をセキュリティ研修として導入を検討する企業向けのドキュメントです。参加者が習得できるスキル、セキュリティフレームワークとの対応関係、評価指標について説明します。

## 参加者が学べること

### インシデントレスポンスの実践

GameDay では、リアルタイムで攻撃を受けながら防御します。参加者は以下を体験します。

- 攻撃の検知と影響範囲の特定
- 優先順位に基づくインシデント対応の判断
- チーム内での役割分担と連携
- 時間的プレッシャーの中での意思決定

### AWS セキュリティのベストプラクティス

攻撃カタログには、AWS 環境で頻繁に発生するセキュリティ問題が含まれています。

| 攻撃テーマ | 学習できる AWS セキュリティ項目 |
|---|---|
| SQL Injection | パラメータ化クエリによるインジェクション対策 |
| Remote Code Execution | 不要なエンドポイントの削除とアクセス制御 |
| Password Rotation | AWS Secrets Manager によるシークレット管理 |
| SSRF Attack | URL 検証と内部ネットワークアクセスの制限 |
| Leaked Credentials | 認証情報の安全な管理とローテーション |
| Hacked Bucket | S3 Block Public Access とバケットポリシー |
| Data Exfiltration | VPC エンドポイントと CloudTrail による監視 |
| Compromised Website | CloudFront と WAF によるアプリケーション保護 |
| HA/Resilience Attack | Auto Scaling と Multi-AZ 構成による高可用性 |
| EC2 System Status Check Failed | EC2 Auto Recovery と障害復旧 |

### 脆弱性の特定と修正

参加者は以下のスキルを実践的に身につけます。

- ソースコード内の脆弱性の発見
- 脆弱性の修正方法の調査と実装
- 修正のテストと検証
- ヒントシステムを活用した段階的な学習

### チームでのセキュリティ対応

GameDay はチーム単位で参加するため、以下の協調スキルが養われます。

- 攻撃と防御の役割分担
- リアルタイムでの情報共有と状況判断
- 同盟を活用した戦略的な協力
- 限られたポイントを攻撃購入・ヒント取得・防御のいずれに配分するかの判断

## セキュリティフレームワークとの対応

### NIST サイバーセキュリティフレームワーク（CSF）

GameDay の活動は NIST CSF の 5 つの機能と対応しています。

**識別（Identify）**

- 自チームの AWS 環境にある脆弱性を特定する
- 攻撃カタログから潜在的なリスクを評価する
- ポイント（リソース）の優先配分を判断する

**防御（Protect）**

- 脆弱性の修正によるセキュリティ対策の実装
- S3 バケットポリシーの最小権限設定と IAM ロールの制限
- WAF や VPC エンドポイントによる境界防御
- Secrets Manager によるシークレットの保護

**検知（Detect）**

- ヘルスチェックによるサービス異常の検出
- 攻撃ログの監視とパターン分析
- 司令部ダッシュボードでのリアルタイム監視

**対応（Respond）**

- 攻撃を受けた際の優先順位判断
- ヒントシステムを活用した修正手順の取得
- チーム内での対応策の迅速な実行
- 同盟を活用した協調的な対応

**復旧（Recover）**

- ダウンしたサービスの復旧手順の実施
- Auto Scaling や Multi-AZ による自動復旧の設定
- ヘルスチェック正常化によるスコア回復

### AWS Well-Architected Framework セキュリティの柱

GameDay の問題は AWS Well-Architected Framework のセキュリティの柱に沿って設計されています。

| 設計原則 | GameDay での実践 |
|---|---|
| 強力なアイデンティティ基盤 | IAM ポリシーの最小権限設定、認証情報の適切な管理 |
| トレーサビリティの確保 | CloudTrail によるログ監視、攻撃ログの分析 |
| 全レイヤーへのセキュリティ適用 | ネットワーク、アプリケーション、データ各層での防御 |
| セキュリティのベストプラクティスの自動化 | Auto Recovery、WAF ルールによる自動防御 |
| 転送中・保存時のデータ保護 | S3 バケットポリシー、VPC エンドポイントの活用 |
| データに人の手を出さない | Secrets Manager による自動化されたシークレット管理 |
| セキュリティイベントに備える | インシデントレスポンスの実践訓練 |

## 評価指標

### スコア内訳分析

GameDay 終了後のスコアを分析することで、チームの強みと弱みを評価できます。

**攻撃スコア**

- 攻撃購入数: 積極性の指標
- 攻撃成功率: 攻撃対象の選定能力
- 攻撃報酬の合計: 攻撃戦略の有効性

**防御スコア**

- 脆弱性修正数: 防御の網羅性
- 修正報酬の合計: 防御活動の成果
- 攻撃防御回数: 修正が攻撃阻止に貢献した回数

**運用スコア**

- ヘルスチェック合格率: サービス安定性の維持能力
- ヘルスチェック報酬の合計: 継続的な運用品質

### 防御修正率

チームの脆弱性修正率は、セキュリティ対応力の指標です。

```
防御修正率 = 修正済み脆弱性数 / 全脆弱性数 x 100
```

- 80％ 以上: 優秀。包括的なセキュリティ対応能力がある
- 50％ 〜 79％: 標準的。主要な脆弱性には対応できている
- 50％ 未満: 改善が必要。脆弱性の特定・修正スキルの強化を推奨

### レスポンスタイム

攻撃を受けてから脆弱性を修正するまでの時間を測定できます。

- 攻撃ログの時刻と脆弱性修正報告の時刻の差分で算出
- レスポンスタイムが短いチームほど、インシデント対応力が高い

### 総合評価の観点

| 評価カテゴリ | 指標 | 優秀な基準 |
|---|---|---|
| 攻撃力 | 攻撃成功率 | 70％ 以上 |
| 防御力 | 脆弱性修正率 | 80％ 以上 |
| 運用力 | ヘルスチェック合格率 | 90％ 以上 |
| 判断力 | ポイント効率（最終スコア / 消費ポイント） | 1.0 以上 |
| 協調力 | 同盟活用、投票獲得数 | チーム間の定性評価 |

## 導入効果

### 従来のセキュリティ研修との違い

| 項目 | 座学研修 | TenkaCloud GameDay |
|---|---|---|
| 学習形式 | 受動的 | 能動的・競技型 |
| 実践性 | 事例紹介中心 | 実際の AWS 環境で実行 |
| 即時フィードバック | なし | スコアとヘルスチェックで即時反映 |
| チームワーク | 限定的 | 攻防を通じた協力が必須 |
| 継続性 | 単発 | 定期開催が容易 |

### 推奨する実施頻度

- 四半期ごと: 新しい脆弱性やシナリオを追加して繰り返し実施
- チーム編成を変える: 異なるメンバーとの協働で新たな気づきを得る
- 難易度を段階的に上げる: 初回はヒントを無料にするなど調整可能
