Event-day operations runbooks

Japanese: README.ja.md

This directory is the operator-facing playbook for running a small TenkaCloud event end-to-end without relying on maintainer memory. Each runbook is self-contained and lists Audience, When to use, Step-by-step + estimated time, and an "If it goes wrong" branch.

The runbooks assume Lite mode (make deploy) as the default, because most paid hosted events are one organizer / one event. SaaS mode notes are called out inline.

Index

# Runbook Audience When to use Estimated time
1 Pre-event checklist Facilitator T-7 / T-1 / T-0 staged readiness 30 min × 3 sessions
2 Dry run Operator Within 7 days before the event (mandatory) 90 min
3 Participant onboarding Facilitator Event-day morning, before kickoff 20 min
4 Live monitoring On-call operator During the event window Continuous
5 Incident response On-call operator Triggered by alarm or participant report 5 to 30 min per incident
6 Teardown Operator Within 24 hours after the event ends 60 min
7 Multi-cloud providers Operator Setup — only if a problem targets Sakura / Azure / GCP, before you deploy it 20 min per team per provider

How the runbooks cross-link

  • Pre-event checklist links to Dry run as the T-7 gate ("you cannot skip the dry run").
  • Live monitoring links to Incident response at the triage decision point.
  • Incident response and Teardown both cross-link back to Live monitoring for context on what was already observed.
  • Multi-cloud providers is a setup runbook (not event-day): run it per team before deploying a non-AWS problem, and its per-provider destroy rolls up into Teardown.
  • All runbooks cite the relevant ADRs as the source of truth for design decisions:
    • ADR-006: Notifications — operator-to-participant messaging contract.
    • ADR-014: EventBridge-driven state reconciliation — how state converges without SSE / WebSocket.

What is out of scope

  • Auto-detection / auto-rollback code (tracked separately under #1352). These runbooks describe operator action only.
  • Post-event survey / commercial follow-up templates (tracked under the broader launch-readiness epic #1336).

Reading order for a new operator

  1. Pre-event checklist — read it once end-to-end, then schedule the T-7 / T-1 / T-0 reminders.
  2. Dry run — execute it at least once. The dry run is the gate, not the production event.
  3. Bookmark Live monitoring and Incident response side by side. They are the two tabs you keep open during the event.
  4. Teardown — review the day before so you do not stall after the event ends.
