# TenkaCloud ユーザーストーリー

E2E テストの基盤となるユーザーストーリーとシナリオ定義。

## ペルソナ

### プラットフォーム管理者（Platform Admin）
- TenkaCloud 全体を運用する人
- テナントの作成・管理・課金を担当
- Control Plane を使用

### テナント管理者（Tenant Admin）
- 企業・教育機関の競技イベント主催者
- 問題作成、バトル開催を担当
- Application Plane を使用

### 競技者（Participant）
- バトルに参加するエンジニア
- 問題を解き、スコアを競う
- Application Plane を使用

---

## 1. テナント管理（Control Plane）

### US-1.1: 新規テナント登録

**As a** プラットフォーム管理者
**I want to** 新しいテナントを登録したい
**目的:** 企業・教育機関が TenkaCloud を利用開始できるようにする。

#### 受け入れ基準
- [ ] テナント名、連絡先メール、プランを入力して登録できる
- [ ] 登録完了後、テナント一覧に表示される
- [ ] 一意のテナント ID が自動生成される
- [ ] 初期ユーザー（テナント管理者）が自動作成される

#### テストシナリオ
```gherkin
Scenario: テナント登録フロー
  Given プラットフォーム管理者としてログインしている
  When テナント登録フォームに以下を入力する
    | フィールド | 値 |
    | テナント名 | Acme Corp |
    | メール | admin@acme.example.com |
    | プラン | Enterprise |
  And 「登録」ボタンをクリックする
  Then 「テナントを登録しました」と表示される
  And テナント一覧に「Acme Corp」が表示される
```

### US-1.2: テナント一覧表示

**As a** プラットフォーム管理者
**I want to** 登録済みテナントの一覧を確認したい
**目的:** テナントの状況を把握できるようにする。

#### 受け入れ基準
- [ ] テナント名、ステータス、作成日時が表示される
- [ ] ステータス（Active/Suspended）でフィルタできる
- [ ] テナント名で検索できる
- [ ] ページネーションが動作する（20 件/ページ）

### US-1.3: テナント詳細・編集

**As a** プラットフォーム管理者
**I want to** テナントの詳細を確認・編集したい
**目的:** テナント情報を最新に保てるようにする。

#### 受け入れ基準
- [ ] テナント詳細ページでプラン、利用状況を確認できる
- [ ] テナント名、連絡先を編集できる
- [ ] プランを変更できる
- [ ] テナントを一時停止（Suspend）できる

## 2. 問題管理（Application Plane）

### US-2.1: 問題一覧表示

**As a** テナント管理者
**I want to** テナント内の問題一覧を確認したい
**目的:** バトルで使用する問題を選択できるようにする。

#### 受け入れ基準
- [ ] 問題タイトル、難易度、カテゴリが表示される
- [ ] 難易度（Easy/Medium/Hard）でフィルタできる
- [ ] タイトルで検索できる
- [ ] 作成日時でソートできる

#### テストシナリオ
```gherkin
Scenario: 問題一覧をフィルタする
  Given テナント管理者としてログインしている
  And 以下の問題が存在する
    | タイトル | 難易度 |
    | S3 バケット作成 | Easy |
    | VPC 構築 | Medium |
    | EKS クラスタ構築 | Hard |
  When 難易度フィルタで「Hard」を選択する
  Then 「EKS クラスタ構築」のみが表示される
```

### US-2.2: 問題作成（手動）

**As a** テナント管理者
**I want to** 新しい問題を手動で作成したい
**目的:** カスタマイズした問題を出題できるようにする。

#### 受け入れ基準
- [ ] タイトル、説明、難易度、制限時間を入力できる
- [ ] 採点基準（チェック項目）を複数設定できる
- [ ] ヒントを複数設定できる（段階的に公開）
- [ ] 下書き保存ができる
- [ ] プレビューで競技者視点の表示を確認できる

#### テストシナリオ
```gherkin
Scenario: 新しい問題を作成する
  Given テナント管理者としてログインしている
  When 「問題作成」ページを開く
  And 以下を入力する
    | フィールド | 値 |
    | タイトル | Lambda 関数デプロイ |
    | 説明 | S3 トリガーで起動する Lambda 関数を構築せよ |
    | 難易度 | Medium |
    | 制限時間 | 30 分 |
  And 採点基準を追加する
    | 項目 | 配点 |
    | Lambda 関数が存在する | 30 |
    | S3 トリガーが設定されている | 40 |
    | IAM ロールが最小権限 | 30 |
  And 「公開」ボタンをクリックする
  Then 問題一覧に「Lambda 関数デプロイ」が表示される
```

### US-2.3: 問題作成（AI 支援）

**As a** テナント管理者
**I want to** AI に問題を生成させたい
**目的:** 効率的に多様な問題を作成できるようにする。

#### 受け入れ基準
- [ ] テーマ（例：「初心者向け S3」）を入力して生成できる
- [ ] 難易度を指定できる
- [ ] 生成された問題を編集して調整できる
- [ ] 採点基準も自動生成される
- [ ] 生成結果を破棄して再生成できる

#### テストシナリオ
```gherkin
Scenario: AI で問題を生成する
  Given テナント管理者としてログインしている
  When 「AI 問題生成」ページを開く
  And 以下を入力する
    | フィールド | 値 |
    | テーマ | EC2 インスタンスの基本 |
    | 難易度 | Easy |
    | 対象サービス | EC2, VPC, Security Group |
  And 「生成」ボタンをクリックする
  Then 生成中のローディングが表示される
  And 問題のプレビューが表示される
  And 「採用」「再生成」「破棄」ボタンが表示される
```

### US-2.4: 問題編集・削除

**As a** テナント管理者
**I want to** 既存の問題を編集・削除したい
**目的:** 問題を改善・整理できるようにする。

#### 受け入れ基準
- [ ] タイトル、説明、採点基準を編集できる
- [ ] バトルで使用中の問題は削除できない（警告表示）
- [ ] 削除前に確認ダイアログが表示される
- [ ] 編集履歴が保存される

## 3. バトル管理（Application Plane）

### US-3.1: バトル作成

**As a** テナント管理者
**I want to** 新しいバトルを作成したい
**目的:** 競技イベントを開催できるようにする。

#### 受け入れ基準
- [ ] バトル名、説明、開始・終了日時を設定できる
- [ ] 使用する問題を複数選択できる
- [ ] 参加者数の上限を設定できる
- [ ] 公開/非公開（招待制）を選択できる
- [ ] チーム戦/個人戦を選択できる

#### テストシナリオ
```gherkin
Scenario: 新しいバトルを作成する
  Given テナント管理者としてログインしている
  And 以下の問題が公開されている
    | タイトル |
    | S3 バケット作成 |
    | VPC 構築 |
  When 「バトル作成」ページを開く
  And 以下を入力する
    | フィールド | 値 |
    | バトル名 | 社内 AWS 道場 第1回 |
    | 開始日時 | 2026-02-15 10:00 |
    | 終了日時 | 2026-02-15 12:00 |
    | 形式 | 個人戦 |
  And 問題「S3 バケット作成」「VPC 構築」を選択する
  And 「作成」ボタンをクリックする
  Then バトル一覧に「社内 AWS 道場 第1回」が表示される
  And ステータスが「Scheduled」である
```

### US-3.2: バトル参加登録

**As a** 競技者
**I want to** バトルに参加登録したい
**目的:** 競技に参加できるようにする。

#### 受け入れ基準
- [ ] 公開バトルの一覧が表示される
- [ ] 「参加登録」ボタンで登録できる
- [ ] 定員に達したバトルは「満員」と表示される
- [ ] 招待制バトルは招待コードで参加できる
- [ ] 参加登録済みのバトルは「登録済み」と表示される

### US-3.3: バトル実行

**As a** 競技者
**I want to** バトル中に問題を解きたい
**目的:** スコアを獲得できるようにする。

#### 受け入れ基準
- [ ] バトル開始時刻になると問題が表示される
- [ ] 残り時間がカウントダウン表示される
- [ ] 問題ごとに「提出」ボタンがある
- [ ] 提出すると自動採点が実行される
- [ ] スコアがリアルタイムで更新される
- [ ] ヒントを段階的に取得できる（ペナルティあり）

#### テストシナリオ
```gherkin
Scenario: 問題を解いて提出する
  Given バトル「社内 AWS 道場 第1回」に参加登録済み
  And バトルが進行中である
  When バトル画面を開く
  Then 問題リストが表示される
  And 残り時間が表示される
  When 問題「S3 バケット作成」を選択する
  And クラウド環境で S3 バケットを作成する
  And 「提出」ボタンをクリックする
  Then 「採点中...」と表示される
  And 採点結果（スコア、フィードバック）が表示される
```

### US-3.4: リーダーボード

**As a** 競技者
**I want to** リーダーボードを確認したい
**目的:** 自分の順位を把握できるようにする。

#### 受け入れ基準
- [ ] リアルタイムでランキングが更新される
- [ ] 順位、参加者名、スコア、最終提出時刻が表示される
- [ ] 自分の行がハイライトされる
- [ ] バトル終了後もリーダーボードを閲覧できる
- [ ] チーム戦の場合はチーム単位で表示される

## 4. 認証・認可

### US-4.1: ログイン

**As a** ユーザー
**I want to** ログインしたい
**目的:** 自分の権限でサービスを利用できるようにする。

#### 受け入れ基準
- [ ] Auth0 経由でソーシャルログイン（Google/GitHub）できる
- [ ] ログイン後、ロールに応じた画面にリダイレクトされる
- [ ] セッションが 7 日間有効
- [ ] 複数デバイスで同時ログイン可能

### US-4.2: 権限制御

**As a** システム
**I want to** ユーザーの権限を制御したい
**目的:** 不正なアクセスを防げるようにする。

#### 受け入れ基準
- [ ] プラットフォーム管理者のみ Control Plane にアクセスできる
- [ ] テナント管理者のみ問題・バトルを作成できる
- [ ] 競技者は自分が参加登録したバトルのみ参加できる
- [ ] 他テナントのデータにはアクセスできない

## 5. エッジケース・エラーハンドリング

### US-5.1: ネットワークエラー

**As a** ユーザー
**I want to** ネットワークエラー時にエラー内容と対処法のフィードバックを受けたい
**目的:** 状況を理解して対処できるようにする。

#### 受け入れ基準
- [ ] API タイムアウト時にリトライボタンが表示される
- [ ] オフライン時に「接続がありません」と表示される
- [ ] 入力途中のデータはローカルストレージに一時保存される

### US-5.2: 同時編集

**As a** テナント管理者
**I want to** 同時編集の競合を検知したい
**目的:** データが上書きされないようにする。

#### 受け入れ基準
- [ ] 他ユーザーが編集中の問題を開くと警告が表示される
- [ ] 保存時にバージョン競合があれば差分を表示する
- [ ] 強制上書き or マージを選択できる

### US-5.3: バトル中の異常終了

**As a** 競技者
**I want to** バトル中にブラウザがクラッシュしても復帰したい
**目的:** 競技を継続できるようにする。

#### 受け入れ基準
- [ ] ブラウザを再度開くと直前の状態が復元される
- [ ] 採点中のリクエストは再送される
- [ ] 残り時間は正確に維持される（サーバー基準）

## テスト優先度

| 優先度 | ストーリー | 理由 |
|--------|------------|------|
| P0（必須） | US-2.1, US-2.2 | コア機能。問題なしではバトルできない |
| P0（必須） | US-3.1, US-3.3 | コア機能。バトルの作成・実行 |
| P0（必須） | US-4.1 | 認証なしでは何もできない |
| P1（重要） | US-1.1, US-1.2 | テナント管理。新規利用開始に必要 |
| P1（重要） | US-3.2, US-3.4 | バトル体験の重要な要素 |
| P2（通常） | US-2.3, US-2.4 | AI 生成は差別化要素だが必須ではない |
| P2（通常） | US-4.2, US-5.* | セキュリティ・エラーハンドリング |
