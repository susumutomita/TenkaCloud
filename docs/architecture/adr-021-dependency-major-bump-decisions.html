ADR-021: Dependency major bump 判断 — 採否と棚卸し

Status: Accepted (2026-05-18) · Issue: goal "ライブラリのバージョンが古くてPRが大量に来ているので中身を見て最新に指定" の精査証跡

背景

Dependabot からの小刻みな PR (= patch / minor)、 および 累積された major bump 候補をまとめて棚卸しした。 semver-compat 範囲は PR #972 (= semver-compat bulk bump) で一括取り込み済。 本 ADR は 残った major bump の各 package に対して、 upgrade / keep / defer のいずれかを採るかを決定する 証跡である。

方針: "latest に上げない理由を持つ" バージョン pin を default とし、 latest を採用するものは 必ず影響範囲を読んだ上で採用する。 「latest 自動追随」 は SaaS の安定性と相性が悪い (= 競技中の deploy で Bun/Vite/TypeScript 等が突如 break すると参加者に直接影響)。

採否 matrix

packagecurrentlatest判断理由 + 採用 trigger
zod 3.25.76 4.4.3 defer zod 4 は z.string().email() 等が deprecated / 別 helper 化される 破壊変更。 frontend (admin-console / application-admin-console / participant-portal) + backend (problem-deploy handlers / trust-bridge) で z. 呼び出し箇所が 100+ あり、 回帰リスクが大きい。 採用 trigger: zod 4 移行 codemod が出るか、 dependency の peer 制約で要求された時。
typescript 5.9.3 6.0.3 defer TS 6 は --isolatedDeclarations 等の strict 化 + decorator 仕様変更を含む。 Vite plugin / cdk / hono / aws-sdk SDK の type compatibility が完全に追随していない可能性があり、 typecheck 1300+ source が一気に落ちる risk。 採用 trigger: aws-sdk-js-v3 + aws-cdk-lib + vite plugin の type 互換が確認できた後。 6.x の patch release (6.0.x → 6.1.x) で stabilize を待つ。
vite 7.3.3 8.0.13 defer Vite 8 は vitest@4 の peer dep を要求する可能性 (= vitest 5 で揃える必要)、 HMR の挙動変更、 dev server CLI フラグ変更。 我々の vite.config.ts は 3 SPA で書き込みがあり 総合 break risk。 採用 trigger: vitest と vite-plugin-react-swc の vite 8 対応 release が安定してから。
jsdom 25.0.1 29.1.1 defer 4 majors 遅れ。 jsdom 26-29 は DOM Spec 最新仕様への追従で fetch / URL / Custom Element 周りで behavior 変更。 既存 test (= 3 SPA + infrastructure 計 ~570 件) で document / window stub を使う test が壊れる risk。 採用 trigger: vitest 5 と一緒に大移行する。 単独 bump は ROI 低い。
@types/node 24.12.4 25.8.0 defer @types/node v25 は Node.js 24 LTS と整合しない (= 25.x の API 型を含む)。 我々の Lambda runtime は Node 22 (= AWS managed)、 CI / local dev は Node 24。 採用 trigger: Lambda の Node 25 runtime が GA かつ我々が runtime を 25 に上げた後。
@aws-cdk/aws-lambda-python-alpha 2.140.0-alpha.0 2.254.0-alpha.0 defer alpha API なので minor でも壊れ得る。 現状本 repo では 使用していない (= インポート箇所 0)。 transitive dep として残っている。 採用 trigger: 実際の 使用箇所が出てから bump。 それまで放置で問題なし。
@cdklabs/sbt-aws 0.3.9 0.9.5 defer SBT (SaaS Builder Toolkit) は 0.4 / 0.5 で ControlPlane の internal API が再設計され、 0.6+ で ControlPlane construct prop が完全 incompatible (= cognito / EventBridge wiring が変わる)。 本 repo の control-plane-stack.ts + tenant pipeline が再書き換え必要。 採用 trigger: ControlPlane stack を新 API に rewrite する PR を別立て (= 1 sprint かかる本格 migration)。 それまで 0.3.9 で安定運用。
ajv 8.18.0 8.20.0 keep (pin) 意図的 pin。 ajv-formats@3 が nested ajv@8.18 を bundle するため、 top hoist を 8.20 にすると ajv の Vocabulary / Scope identity が 2 種類になり TS type 衝突 (= config-loader.ts typecheck fail)。 patch なので得るものが少なく、 8.18 pin で dedupe を維持 (= PR #972 で決定済、 本 ADR で再確認)。 採用 trigger: ajv-formats が ajv@8.20+ peer に追従してから。
jsdom (& vite & vitest) — — defer (group) 上記 jsdom / vite / typescript は 同時期に 上げると test infra ごと壊れる懸念。 1 sprint まとめて 「test infra 移行 PR」 として上げる方が ROI が高い (= 1 PR で全部直す、 分割上げで途中状態に苦しまない)。
ulid 2.4.0 3.0.2 defer ulid 3 は ESM-only + named export 専用化。 import { ulid } from "ulid" 形は 動くが、 同時に monotonicFactory 等の utility が rename / 廃止。 検索範囲は限定的 (= 4 ファイル) だが、 timestamp ordering を返す関数の broken-glass で deploy job ID 採番が 壊れた場合の影響が大きい。 採用 trigger: 単独 PR で 4 ファイル分の影響を test で固めてから。
markdownlint-cli2 0.21.0 0.22.1 defer 0.22 で MD034 / MD040 等の rule default が変更され、 既存 docs/*.md 100+ ファイルで lint error が出る可能性高 (= upstream changelog 確認済)。 移行は 1 PR で全 markdown を fix する別作業。 採用 trigger: docs lint sprint で fix と同時に。
aws-cdk (CLI) 2.1118.0 2.1122.0 upgrade 本 ADR の PR で 2.1122.0 に upgrade。 aws-cdk-lib 2.254.x との整合性、 cdk synth / cdk diff の挙動に影響する patch リリースのみ。 typecheck + synth は通過確認済。
textlint 15.7.0 15.7.1 upgrade 本 ADR の PR で 15.7.1 に upgrade。 semver patch、 単独で `bun update textlint` で取り込み。 全 markdown lint pass 確認済。

方針 summary

採用 (= 本 PR で取り込み)

  • aws-cdk 2.1118 → 2.1122 (CLI、 patch)
  • textlint 15.7.0 → 15.7.1 (patch)

意図的に keep (= ADR で固定理由を持つ)

  • ajv 8.18.0 (= ajv-formats nested ajv との型衝突回避、 PR #972 で確認済)

Defer (= 採用 trigger を持つ、 単独 PR で上げる)

  • zod 3 → 4: backend / frontend 100+ 箇所、 migration codemod 待ち
  • typescript 5 → 6: aws-sdk / cdk / vite plugin type 互換 stabilize 待ち
  • vite 7 → 8 + vitest + jsdom: test infra 同時移行 sprint
  • @types/node 24 → 25: Lambda Node 25 runtime GA 待ち
  • @cdklabs/sbt-aws 0.3 → 0.9: ControlPlane stack rewrite sprint
  • ulid 2 → 3: ESM-only 化、 4 ファイルの単独 PR 必要
  • markdownlint-cli2 0.21 → 0.22: docs lint sprint と同時
  • @aws-cdk/aws-lambda-python-alpha: 未使用 transitive、 採用時に bump

運用

  • 本 ADR は 四半期ごとに見直す。 「採用 trigger」 を満たした項目は別 PR で上げ、 本 ADR を更新する
  • 新たな patch / minor 互換 update は dependabot PR で自動取り込み
  • 新たな major bump 候補が増えたら本 ADR に行を追加する (= 「latest 自動追随」 を default にしない方針を文書化で守る)
