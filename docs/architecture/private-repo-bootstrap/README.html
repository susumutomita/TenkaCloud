TenkaCloudChallenges private repo bootstrap

Issue #643 / ADR-008 Phase 4。 本 directory は user が TenkaCloudChallenges private repo を新規作成する際の bootstrap テンプレ集です。 Claude 側で投入できる artifact (= workflow YAML / IAM CFn テンプレ) を pre-position し、 user は GitHub 上で repo を作成して ここのファイルをコピーするだけで Phase 4 を稼働させられます。

役割分担:
  • Claude 担当 (= ここに済): workflow YAML / IAM trust CFn / README
  • user 担当: GitHub repo 作成、 OIDC IAM Stack の deploy、 GitHub Actions secret bind、 1 問目の private 移行

1. 概要

ADR-008 は問題ペイロード (= microservice-migration-battle の services コード等の「答え」) を public な本体 repo から private repo に分離する アーキテクチャ。 本 bootstrap で揃えるのは private repo 側 の構造です: 

TenkaCloudChallenges/   (= 新規作成、 private)
├── problems/
│   └── <category>/<id>/
│       ├── metadata.json
│       └── template.yaml
├── .github/workflows/
│   ├── publish.yml          # ここから copy
│   └── catalog-pr.yml       # ここから copy
└── README.md

2. user 担当の手順

  1. private repo 作成: GitHub UI で TenkaCloudChallenges を visibility=private で新規作成 (owner: susumutomita or org)
  2. 本 directory の YAML をコピー:
    • publish.yml → .github/workflows/publish.yml
    • catalog-pr.yml → .github/workflows/catalog-pr.yml
  3. OIDC IAM Stack を deploy: 本 directory の oidc-iam-trust.template.yaml を運営 AWS account に aws cloudformation deploy で投入。 出力された Role ARN を repo Actions secret AWS_CHALLENGE_PUBLISH_ROLE_ARN に bind
  4. 初期 README.md を作成: 本 directory の private-repo-README.template.md を参考にコピーして TenkaCloudChallenges/README.md に展開
  5. 1 問目を private 移行 (= 任意): 本体 repo の problems/battles/microservice-migration-battle/services/ を private repo に move、 本体側 metadata.json の visibility を private に変更
S3 bucket / Step Functions 側の infra は別 issue: ChallengePayloadStack (= tc-challenges-${env} bucket + Step Functions env override) は #642 で別 tracking。 本 bootstrap は repo 構造のみを扱う。

3. ファイル一覧

ファイル 目的 コピー先
publish.yml 問題 dir 変更 → zip 化 → S3 upload (= version=git short SHA で pin) TenkaCloudChallenges/.github/workflows/publish.yml
catalog-pr.yml 問題 metadata 変更 → 本体 repo の problems/index.json に diff PR TenkaCloudChallenges/.github/workflows/catalog-pr.yml
oidc-iam-trust.template.yaml GitHub OIDC provider + Role (= S3 upload + PR 作成権限) 運営 AWS account の CloudFormation (= 別 stack)
private-repo-README.template.md private repo 側の README 雛形 (= contributor 向け説明) TenkaCloudChallenges/README.md

4. 注意

  • publish.yml は min-release-age=168h と整合 (= mini Shai-Hulud 第二波対策、 AGENTS.md / .npmrc 参照)
  • OIDC trust の sub 条件は repo 名 + branch を絞る (= repo:susumutomita/TenkaCloudChallenges:ref:refs/heads/main 相当) で fork 経由の濫用を防ぐ
  • catalog-pr.yml の bot token は GitHub App ベースが望ましい (= PAT rotation の手間を省く)。 初期は PAT で動かして後で App 化
