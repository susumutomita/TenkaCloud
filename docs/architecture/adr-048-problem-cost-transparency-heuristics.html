ADR-048: Problem Cost Transparency Heuristics

Status: Accepted

Date: 2026-06-19

Scope: Problem authoring, catalog selection, and operator cost guardrails.

Context

TenkaCloud problem templates are CloudFormation files deployed into competitor AWS accounts. Authors and operators need to know which resources can create standing spend before a problem is deployed. The existing metadata already records estimated play time, but it does not derive AWS resource cost from the deploy template. Relying only on author-declared estimates is weak because expensive resources can be omitted accidentally.

The check must run in local authoring, CI, and AI-assisted problem creation without AWS credentials or network access. AWS Pricing APIs are useful for precise follow-up analysis, but they are mutable, region-specific, credentialed, and too slow or unavailable for a required pre-commit invariant.

Decision

Use an offline deterministic cost heuristic as the primary cost transparency source. The model scans each problem's CloudFormation Resources and maps known resource types to a rough hourly USD value, an alwaysOn flag, and a risk level. The first implementation is exposed through bun run scripts/tenkacloud-problem.ts cost <id>.

SourceRoleRequired?
Offline heuristic table Authoring and CI-safe baseline. Derives resource inventory, per-hour estimate, typical-session estimate, and per-day-if-left-running risk. Yes
AWS Pricing API or AWS Pricing MCP Optional precision pass when an author wants regional or SKU-specific detail. No
Author-declared catalog metadata Human-friendly supplemental copy for cards and catalog docs. No, and it must not replace derived flags

The derived estimate is intentionally approximate. Its job is to make cost visible and to flag resources that keep billing when no participant is actively using the problem: NAT gateways, RDS instances, load balancers, EC2 instances, WAF web ACLs, public IPv4 allocation, and similar standing capacity.

Consequences

  • Problem authors get a fast local command before deploy, using the same source template that CloudFormation will deploy.
  • CI and AI-assisted authoring can run the check offline without credentials.
  • Unknown resource types are surfaced for manual review instead of silently assuming zero cost.
  • The estimate is not a bill forecast. Regional price changes, free-tier eligibility, usage-based charges, storage growth, and data transfer still require human review for expensive or customer-facing deployments.
Operational boundary: This ADR defines the shared cost model and authoring surface. Operator notifications for leaked resources after teardown are a later operate-time slice and should use the same derived resource inventory where practical.

Implementation Notes

The initial platform-owned slice adds the deterministic model under scripts/lib/, the tenkacloud-problem cost subcommand, unit tests, and authoring documentation. Later slices can feed the same model into admin-console deploy confirmation and catalog rendering.
