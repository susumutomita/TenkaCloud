ADR-014: Polling-first realtime model with EventBridge-driven reconciliation

Accepted   Scope: all SPAs (freshness of server state), backend schedulers

Context

Competition UIs want live-feeling data: deployment progress, scores, leaderboard, event lifecycle. The obvious web answers are WebSocket or Server-Sent Events, but every TenkaCloud backend is a request-scoped Lambda behind API Gateway HTTP API, and the platform is engineered to fit the AWS Free Tier (see the DynamoDB 1/1 provisioned-capacity rule). Persistent connections fight both constraints:

  • WebSocket requires API Gateway WebSocket APIs plus a connection registry table and fan-out code — new cost, new state, new failure modes.
  • SSE from Lambda ties a function instance to each open client for its full duration.
  • Push also needs a fallback anyway: browsers sleep tabs, conference Wi-Fi drops connections.

Pure client polling alone has its own trap: state that changes with time rather than with a user action (a scheduled event start, a deploy whose CloudFormation stack finished, a teardown deadline) would only converge when some client happens to poll, and server-side writes would be driven by read traffic.

Decision

LayerRule
Frontend Polling only for server-state freshness on AWS-backed surfaces; introducing SSE or WebSocket there is prohibited — because those backends are request-scoped Lambdas behind API Gateway HTTP API and the platform is sized for the AWS Free Tier. A persistent connection needs an API Gateway WebSocket API, a connection-registry table charged against the DynamoDB 1/1 provisioned-capacity rule, and fan-out code; SSE instead pins a Lambda instance per open client for its full duration. All polling goes through the shared usePolling hook (@tenkacloud/web-kit); apps do not hand-roll data-fetch timers. Intervals are named constants per surface (e.g. constants/polling.ts in the tenant admin console), not inline numbers.

Out of scope: local play (scripts/local-play). It runs as one long-lived local node:http process with SQLite on the participant's own machine — no Lambda, no DynamoDB, no API Gateway, no per-connection cost — so not one of the reasons above applies. Interactive transports there (for example a shell attached to a problem container) are judged on their own merits and are not barred by this ADR. This rule is a consequence of the AWS runtime, not a stylistic preference: where that runtime does not impose it, it does not bind.
Backend Time-driven state transitions are owned by EventBridge-scheduled reconcilers (rate(1 minute)): event status transitions (scheduled start / end), scheduled bulk deploy and teardown firing, and CloudFormation runtime-status reconciliation. Reconcilers are idempotent — they re-derive the desired transition each tick and treat conditional-write conflicts as "another tick already did it".
Contract between the two Clients never cause state transitions by polling; they only observe. The server converges on its own clock, so a client that polls slowly (or not at all) never delays an event start, a teardown, or scoring.

Consequences

  • Freshness is bounded by the poll interval per surface plus at most one reconciler tick (≈1 minute) for time-driven transitions. This is accepted: competition state does not need sub-second delivery.
  • No connection registry, no fan-out infrastructure, no per-connection cost. Every backend request stays a stateless Lambda invocation.
  • Reconcilers must stay idempotent and safe to double-fire; their conditional-write "already done" paths are deliberate and must not be reported as errors.
  • UI code must tolerate seeing the same state twice and state that skips intermediate steps between polls.

Alternatives considered

AlternativeWhy rejected
API Gateway WebSocket APIConnection table + fan-out Lambda + reconnect handling; breaks the zero-persistent-infrastructure model and the free-tier budget for a marginal UX gain.
AppSync subscriptionsIntroduces a second API technology and schema layer for the same data the HTTP API already serves.
SSE (Lambda response streaming)Holds a Lambda per open client; still needs polling as a fallback, so it adds a path without removing one.
Client-triggered transitions ("lazy cron" on poll)State convergence would depend on read traffic; an event with no watching admin would never start or tear down on time.
