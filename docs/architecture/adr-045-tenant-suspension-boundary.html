ADR-045: Tenant suspension requires explicit state propagation

TenantDetails だけを更新する suspend/resume UI は追加せず、App Plane が信頼できる伝播契約を先に固定する

Status: Accepted 2026-06-18
Decision: Reject UI-only suspension writes
Related: ADR-014, ADR-020, Architecture harness
Tracking: #1768

Context

TenkaCloud already has a destructive tenant offboarding path. It marks a tenant inactive and starts the deprovisioning workflow. Issue #1768 requested a softer suspension mode for unpaid or abusive tenants: preserve tenant data and history, but reject new event creation and problem deployments with StatusCodes.FORBIDDEN.

The safe runtime guard is already present in the App Plane handlers. Deploy and event routes read a trusted JWT claim, custom:isSuspended, and return tenant_suspended before creating new deploy or event work. The admin console also reads an isSuspended tenant attribute and renders suspended tenants distinctly in list and detail views.

The missing part is not a button. The missing part is the propagation contract from the System Admin action to the App Plane authorization decision. SBT's built-in PUT /tenants/{tenantId} endpoint can update arbitrary fields on the Control Plane TenantDetails row, including isSuspended. That row is not read by App Plane handlers, and the tenant Cognito UserPool does not currently define or expose custom:isSuspended as a normal user attribute.

Adding an admin-console suspend/resume control that only calls SBT PUT /tenants/{tenantId} would create an unsafe split-brain state: the Control Plane list would show a suspended tenant while new App Plane event and deploy requests could still be accepted until some separate manual action updates tokens or local App Plane state.

Decision

TenkaCloud will keep custom:isSuspended as the current App Plane enforcement contract and will not add suspend/resume write controls to apps/admin-console until the Control Plane owns an audited propagation path that makes the App Plane decision true. Updating TenantDetails.isSuspended alone is not a valid implementation of tenant suspension.

Accepted now Show isSuspended when the field is present, and reject App Plane create operations when custom:isSuspended=true is present in the caller's token.
Rejected now A UI-only suspend/resume action that writes only TenantDetails and leaves active App Plane sessions unchanged.
Required before UI A Control Plane-owned write path with audit, propagation semantics, tests, and a clear token or App Plane state refresh policy.

Rationale

ConcernReason
Authorization source of truth Deploy and event handlers must decide from trusted tenant-scoped state. A control-plane table update that is not consumed by those handlers is display state, not enforcement.
Plane separation The App Plane should not synchronously read SBT TenantDetails on every tenant request. That would couple tenant runtime operations to the Control Plane data store and work against the architecture harness separation model.
Session semantics A JWT claim approach is simple and tamper-resistant, but existing ID tokens remain valid until expiry unless the design also defines global sign-out, token revocation, or a short enough maximum delay.
Immediate enforcement If suspension must apply immediately, EventBridge-driven propagation to App Plane-owned state is the better fit. That requires new infrastructure, table ownership, and reconciliation behavior, so it should be designed as a Control Plane change.
Operator trust A visible suspend button must mean that new tenant work is actually blocked. Shipping a button before propagation exists would make incident handling look safer than it is.

Accepted Implementation

CapabilityLocationStatus
Render suspended tenants when isSuspended=true apps/admin-console/src/api/tenants.ts, apps/admin-console/src/pages/TenantList.tsx, apps/admin-console/src/pages/TenantDetail.tsx Shipped
Reject problem deploy create and retry while suspended infrastructure/lib/problem-deploy/handlers/deploy-handler/ Shipped
Reject event create and bulk deploy while suspended infrastructure/lib/problem-deploy/handlers/event-handler/ Shipped
Admin-console suspend/resume write control apps/admin-console Rejected until propagation exists

Allowed Future Work

This ADR does not prohibit tenant suspension. It defines the work that must exist before the operator UI is enabled:

  • JWT claim projection path. The Control Plane writes isSuspended, updates the tenant Cognito UserPool or token customization path so custom:isSuspended is emitted, and defines whether existing sessions are revoked or allowed to expire.
  • EventBridge propagation path. The Control Plane emits TenantSuspended and TenantResumed events. App Plane-owned state consumes those events, and deploy/event handlers read that local state before accepting new work.
  • Audit and tests. Suspend and resume actions must be audited, handler tests must cover both rejection and resume, and admin-console tests must prove that the UI cannot show a successful suspend when propagation fails.

Cross-plane direct lookup from App Plane handlers into SBT TenantDetails remains rejected. It adds request-time Control Plane coupling and gives the tenant runtime a dependency on platform administration storage.

Consequences

Positive

  • Operators do not get a misleading suspend button before enforcement exists.
  • The existing App Plane guard remains simple, local to authorization, and covered by tests.
  • Tenant data and history preservation remains compatible with both future propagation paths.

Negative

  • System Admins cannot suspend or resume tenants from apps/admin-console yet.
  • Manual or future Control Plane-owned operations are required to set the trusted custom:isSuspended enforcement state.
  • Immediate suspension semantics still require the propagation path to be implemented.

Implementation Status

No runtime implementation is required for this ADR. Issue #1768 is resolved by accepting the already-shipped display and App Plane guard behavior, and by rejecting the unsafe remaining request: an admin-console suspend/resume write control without an enforcement propagation contract.
