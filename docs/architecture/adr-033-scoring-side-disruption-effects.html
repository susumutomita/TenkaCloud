ADR-033: Scoring-side disruption effects

fire しても採点が動かない disruption に、 実クラウドへの fault 注入を伴わずに「採点上の効果 (減点 / 可用性ダウン)」を与えるための宣言契約と評価経路

Status: Proposed 2026-06-03
Related: ADR-013 (disruption 宣言 / Phase A→B / condition trigger), ADR-031 (cross-account の実 fault 注入 action), ADR-029 (game always ends), ADR-012 (problem = plugin, platform = host)
Issue: #1665 (#1417 の子)

背景 — 何が壊れているか

2026-06-03 のコード監査で、 宣言済の disruption 9 件のうち 採点や挙動に実際の効果を与えるのは 1 件だけ (= microservice-migration-battle/ec2-latency-injection、 ADR-031 の action で実 fault を注入) と判明した。 残り 8 件は fire しても *DisruptionFired イベントの publish と監査行の書き込みで終わり、 競技結果は 1 点も動かない。

とくに stackstack (scoring kind = phased-polling) の 5 件は説明文で「追加減点」「failurePenalty を累積追加」「auth slot を 5 分間 503 にする (= 5 cycle ぶん加点 0)」と 採点上の効果を約束しているが、 それを実現するコード経路が無い。 採点 kind (uptime-multi / phased-polling 等) は実エンドポイントを probe するだけで、 fire 済 disruption を一切参照しない。 = 説明文だけのハリボテ。

これらは 本質的に「ビジネス/シナリオ上の圧力」であり、 競技者アカウントの実インフラを物理的に壊す必要はない (CEO が 5000 人を要求 / Legal が PII を検出 / .env 流出で 5 分間ダウン扱い)。 必要なのは 採点エンジンが、 ある期間その team の点に効果を与えることである。 これは ADR-031 の cross-account 実 fault 注入とは別レイヤの実現手段で、 実クラウドアカウントを必要としない。

決定

disruption 宣言に省略可能な effect を追加し、 採点エンジンがその効果を active window の間だけ 各 tick で KindResult に畳み込む。 disruption の 2 つの実現手段を明確に分離する:

手段実現するもの必要環境ADR
action競技者アカウントの実インフラに 物理 fault (latency / 503 / process kill)。 team の probe がそれを観測して採点が下がる。実クラウド + AssumeRoleADR-031
effect (本 ADR)採点エンジンが直接与える 採点上の効果 (減点 / 指定 slot を fail 扱い)。 物理 fault は起こさない。不要 (platform 内で完結)ADR-033

両者は排他ではない。 1 つの disruption が action と effect の両方を持ってもよい (実 fault + 追加減点)。 どちらも無い disruption は従来どおり「監査のみ」(= 後方互換)。

effect の宣言契約

// metadata.json の disruptions[].effect (省略可)
{
  "kind": "penalty",        // 指定点を減点する (= scoreDelta に負値を加える)
  "points": 50,
  "durationSeconds": 300
}
{
  "kind": "unavailability", // 指定 slot を window 中 fail 扱いにする (= 加点を 0 にし failurePenalty を課す)
  "slots": ["auth"],
  "durationSeconds": 300
}
  • kind は "penalty" | "unavailability" の allow-list。 未知の kind は validator で reject。
  • durationSeconds は正の有限数で上限 3600 (1h)。 ADR-029 の「永続障害禁止」と同じ思想で、 効果は必ず期限切れする。
  • points (penalty) は正の整数。 slots (unavailability) は問題の endpoints[] slot 名の部分集合 (validator が突合)。

評価経路 (active window の解決)

disruption は 2 経路で fire される: condition-triggered (ADR-013 Phase 2、 採点 tick が score/経過/phase で発火) と operator-fired (ADR-031、 operator が API で発火)。 本 ADR は両経路に効果を与えるが、 実装は段階を分ける:

段階fire 経路active window の出所追加 I/O
Phase 1 (本 ADR の初回実装)condition-triggered採点 tick が発火と同時に scoringState.activeEffects[] に {disruptionId, effect, expiresAtMs} を記録。 以降の tick は 自分の行の scoringState だけを読んで適用 + 期限切れを prune。なし (既存の UpdateItem に相乗り)
Phase 2 (follow-up)operator-fired採点 tick が event ごとに disruptions table の AUDIT# 行を 1 回 query し、 当該 team / 効果 window 内の effect を解決。event あたり 1 query/tick

Phase 1 を先に出すのは、 追加の DDB read を一切増やさず (cost-zero 原則) に効果機構を end-to-end で成立させ、 ユニットテストで完全に pin できるからである。 operator-fired (stackstack) は宣言に triggers を足せば Phase 1 で動くか、 Phase 2 の query 経路で拾う。

採点 tick への畳み込み

純関数 applyDisruptionEffects(result, activeEffects, slots, nowMs) が、 kind handler が出した KindResult を受け取り、 active な effect を畳み込んだ新しい KindResult を返す:

  • penalty: scoreDelta -= points、 かつ source="disruption-penalty" の score event を 1 行追加 (= timeline に減点が見える)。
  • unavailability: 対象 slot が uptime-multi / phased-polling の health 集計で fail 扱いになり、 当該 cycle の加点を 0 にして failurePenalty を課す。
  • 期限切れ (nowMs >= expiresAtMs) の effect は適用せず、 scoringState から除く。
  • active effect が無ければ result をそのまま返す (= 完全な後方互換)。

代替案と却下理由

案却下理由
全 disruption を ADR-031 の action (実 fault) で実現する却下。 「CEO が 5000 人要求」「Legal が PII 検出」は物理 fault が存在しない純粋なシナリオ圧力。 実 fault に無理やり変換すると問題設計が歪む。 採点上の効果が正しい抽象。
採点エンジンが毎 tick disruptions table を query して active effect を解決 (Phase 2 を最初からやる)初回は却下。 deployment ごとに read が増え 1/1 RCU を圧迫 (cost-zero 原則に反する)。 condition-triggered を scoringState 相乗りで先に出し、 operator-fired は別 slice で最小コストの query 設計にする。
effect を frontend / scoring の外 (例: 別 Lambda) で適用却下。 採点の単一責務は generic-scoring に集約済 (ADR-012)。 効果も採点 tick 内で畳むのが SRP。
無期限の effect を許す却下。 ADR-029「どの障害も永続しない / ゲームは必ず終わる」に反する。 durationSeconds 必須 + 上限 1h。

影響

  • SCHEMA (submodule problems/SCHEMA.json): disruptions[].effect を追加 (省略可、 enum + required + 上限)。
  • catalog 型 + parser (discover-problems-catalog.ts): DisruptionEffect 型 + parseDisruptionEffect (fail-safe drop、 parseDisruptionAction と同型)。
  • validator (validate-problems): kind allow-list / durationSeconds 上限 / unavailability の slots ⊆ endpoints を enforce。
  • 採点エンジン: scoringState.activeEffects[] + 純関数 applyDisruptionEffects + condition-fire 時の記録 + tick での適用/prune。
  • 参照問題 (submodule): stackstack の減点系 disruption に effect を宣言し、 fire → 減点 → 復帰が実データで動くことを示す。
  • 後方互換: effect 未宣言の disruption / 既存問題は挙動不変。

移行

  1. parent: catalog 型 + parser + 純関数 applyDisruptionEffects + scoringState 拡張 + tick 配線 + unit test (本 ADR の初回 PR、 condition-triggered 経路)。
  2. submodule: SCHEMA + stackstack (または新規参照問題) の effect 宣言 + validator。 parent の pin bump。
  3. follow-up (#1665 Phase 2): operator-fired 経路の active-effect query (最小コスト設計)。

完了の定義は「fire → 採点が宣言どおり下がり、 window 経過で戻る」が ユニットテストで証明されること。 実クラウドや実競技は要らない。 これが満たされて初めて、 当該 disruption を「実装済」と呼ぶ。
