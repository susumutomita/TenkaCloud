ADR-029: Attack-resilience — competition liveness & bounded disruptions

攻撃 / disruption が当たっても競技は必ず終端に達し、 注入された fault は永続しない、 を platform が保証する設計

Status: Accepted 2026-06-02
Related: ADR-012 (Disruption Phase 1), ADR-013 (condition-triggered)
Tracking: #1421 (umbrella #1417)

Context

ADR-013 で condition-triggered disruption (= 観測値に反応した自動 fault injection) を、 #1420 で参加者間 interaction を導入すると、 Battle round 中に競技者は互いを能動的に妨害できるようになる。 これはゲーム性を高める一方で 新しい failure mode を生む:

  • victim の永久ノックアウト: 攻撃を受けたチームが scoreable 状態に戻れず、 そのまま競技終了まで 0 点に固定される。
  • round が終端に達しない: round に終了時刻が無いと leaderboard が確定せず、 「いつ終わったか」 が決まらない (= hang)。 現状 event.endsAt は optional なので、 付け忘れた round は採点が無限に続き得る。
  • 永続 disruption: 一度注入した fault (latency / IAM 剥奪 / endpoint 改ざん) に revert 経路が無いと、 round 全体が壊れたまま進む。

オーナーはこれを hard requirement として明示した: 「攻撃でゲームが終わらなくなる (un-finishable) ことは絶対に許さない」。 本 ADR は「競技は必ず終わる」「fault は必ず revert される」 を platform 不変条件として固定し、 ADR-013 (condition-triggered) / #1420 (inter-team) の上に安全弁を敷く。

Goals

  • Bounded liveness: 全 round が有限時間で必ず terminal state (= 採点停止 + leaderboard 確定) に達する。
  • Time-boxed disruptions: 注入される全 fault に保証された expiry / recovery 経路がある (= 永続 fault を作れない)。
  • Victim recovery: どのチームも有界時間で scoreable 状態に復帰できる primitive を持つ。
  • Scoring floor: 攻撃で score が下限を割って「復帰不能」になることを防ぎ、 leaderboard が単調に終端へ向かう。
  • fail-safe: platform 障害時も上記が静的に保証される (= 動的経路に依存しない構造的保証を優先)。

Decision

D1: Round liveness — 必ず有限な terminal を解決する (採用)

round の終端時刻を「常に有限」 に解決する純関数 resolveRoundTerminalAt(round) を設ける:

terminal = eventEndsAt (明示があれば)
         ?? eventStartsAt + MAX_ROUND_DURATION_MINUTES   // 無ければ cap で必ず終端

MAX_ROUND_DURATION_MINUTES は 正常 round 長ではなく liveness safety-net (= 既定 30 日)。 どの Battle round よりも長く、 deployment の expiresAt (TTL、 通常 数時間〜数日) よりも十分長いので、 正常採点 / evergreen Challenge を打ち切らずに「endsAt 付け忘れ round の無限採点」だけを構造的に排除する。 採点 gate (isScoringActive) はこの解決済み terminal を見て now >= terminal で採点を止める。

D2: Time-boxed disruptions — injection window を round に閉じる (採用)

disruption の発火は isDisruptionWindowOpen(round, now) = (round 開始済み) && !isRoundTerminated(round, now) に限定する。 round は D1 で必ず終端に達するため、 注入された fault の active window は最長でも round 長に収まり、 round 終了時の teardown で competitor stack ごと revert される。 これにより 「終端後に新規 fault は注入されない」「fault は round を超えて永続しない」 を保証する。 condition-triggered (ADR-013 / #1422) と手動 fire (#888) の両発火経路がこの window を consult する。

D3: Victim recovery primitive (採用 / 段階実装)

victim が有界時間で scoreable に戻れる経路を 2 層で用意する:

  • endpoint recovery: ADR-012 Phase 3.A の Endpoint registry (override 行) を使い、 攻撃で壊れた endpoint を victim が再登録 / 再 deploy して採点対象を復元する (= 既存 primitive の再利用)。
  • fault expiry: D2 により fault は round 終端までに必ず切れる。 individual fault の早期 revert は ADR-013 OQ#6 の template-side self-fire rollback (rollbackAfterMinutes) を踏襲する。

D4: Scoring floor & leaderboard liveness (採用 / 段階実装)

攻撃による減点で score が 下限 (floor、 既定 0) を割らないよう clamp する。 これにより victim が「マイナスの底なし沼」 で復帰不能になることを防ぎ、 leaderboard は round terminal (D1) で必ず確定する (= monotone に終端へ向かう)。 floor の clamp は採点書き込み経路に寄せ、 disruption / inter-team 減点と独立に効かせる。

Encoded invariants

本 ADR は次の 2 不変条件を 純関数として encode し test で pin する (= acceptance criteria)。 module: infrastructure/lib/problem-deploy/handlers/generic-scoring-handler/round-liveness.ts。

INV-1 — every round reaches a terminal state.
resolveRoundTerminalAt(round) は eventStartsAt が有効な限り 常に有限な終端 ISO を返す (endsAt ?? startsAt + cap)。 採点 gate isScoringActive がこれを参照し、 endsAt 未設定の round も startsAt + 30d で必ず採点を止める。
INV-2 — no disruption is permanent.
isDisruptionWindowOpen(round, now) は round 開始〜終端の窓でのみ true。 INV-1 で round は必ず終端に達するため、 disruption の injection は有界 window に閉じ、 終端後の新規発火は拒否され、 fault は round teardown で revert される。

Consequences

Positive

  • 攻撃が当たっても競技は構造的に必ず終わる (= オーナーの hard requirement を満たす)。
  • liveness が 静的 (時刻 + cap) に保証されるため、 platform 動的経路の障害時も成立する (fail-safe)。
  • victim が永久ノックアウトされない (recovery primitive + scoring floor)。

Negative

  • 「永遠に走る round」 が表現できなくなる (= 30 日上限)。 evergreen Challenge は deployment TTL で先に終わるため実害は無いが、 30 日超の常設採点が必要なら cap を上げる設定が要る。
  • scoring floor は「下振れの罰」 を弱めるため、 ゲームデザイン上の減点圧を別途設計する必要がある。

Risks

  • cap を短く設定し過ぎると正常 round を誤って打ち切る。 既定 30 日は安全側だが、 設定変更時はレビュー対象。
