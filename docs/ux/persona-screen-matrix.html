Persona × Screen UX matrix

Issue #956 Phase 1 · epic #952 の柱「初見の人が動かせる」 を満たすための情報設計の正本。

このドキュメントが解く問題
  • 直近の audit (image #29 / #32 / #33 / #34 / #35 / #36 / #43 / #45 / #50 等) で表面の UX を 1 件ずつ直してきたが、 画面ごとの IA (= 情報設計) を体系的に見直していない。
  • 結果: 「どの persona が何を見るべきか」 が画面ごとに揺らぎ、 primary action が複数あったり、 不要情報が一等地を占有したりしている。
  • 本 doc は persona × screen の行列 を正本化し、 各画面の primary / secondary / non-target を 1 ページで判断できる base にする。

エラー / 空状態 UX 規約

エラー

API エラーは 技術的 message を競技者に見せない。 既存 FriendlyErrorAlert で次の 4 要素を満たす。

  • 何が起きたか (= 「環境を deploy できませんでした」)、 stack trace ではなく業務語彙で
  • なぜ起きたか (= 「現在の AWS アカウントに deploy 権限が足りません」)、 推測でなく確定できる時だけ書く
  • 次に何をすればよいか (= 「TenantAdmin に ExternalId を rotate するよう依頼してください」)
  • support 連絡先 / correlationId (= 下段に小さく)

空状態

0 件 = empty state はゴミ箱ではなく 次の一歩への入口。 「データがありません」 ではなく「最初に何をすればよいか」 を出す。

画面0 件のとき出すもの
Quests (問題一覧)「event がまだ始まっていません」 + event 開始予定時刻 + 「event 詳細を見る」 link
Scoreboard「まだ採点が始まっていません」 + 1 つ目の team が提出するまでの説明
AdminUsers「ユーザー未招待」 + 「最初のユーザーを招待」 primary button
CompetitorAccounts「verified AWS account が 0 件」 + bootstrap CFn template の copy ボタン + 1 step ガイド
Jobs (Deprovisioning)「すべて健全」 + 直近の deprovisioning 完了履歴 (= 健全さの証明)

Cloudscape 使い方規約

全 SPA (admin-console / application-admin-console / participant-portal / landing-page) で Cloudscape Design System の使い方を揃える。

  • Header variant: h1 はページ 1 つに 1 個。 「画面のタイトル」 と「primary action」 の組合せ。 description は 1 行で済ませる
  • Container vs SpaceBetween: 関連情報は Container で boxing、 独立した section 間は SpaceBetween size="l"。 「box の中にさらに box」 は避ける
  • Table vs Cards: 6 件以下 / 各行に 4 col 以下なら Cards、 それ以上は Table
  • Button variant: primary は 1 画面 1 つだけ。 ほかは normal / link。 destructive (= delete / destroy) は variant=normal + ConfirmModal を必須
  • Modal: 編集系は inline (= Cards 内 SelectInput) を優先、 確認系のみ Modal
  • Breakpoint: ColumnLayout columns={3} は mobile で 1 列に折り返る。 4 col 以上は明示的に grid で書く
