# Host の監査ログ

監査ログはデフォルトで停止しています。Admin が管理画面の「設定」で `audit` を有効にすると、操作記録を host の SQLite データベースに保存します。監査レコードを標準出力・標準エラーへ転送しないため、CloudWatch Logs への監査ログ送信は発生しません。

## 記録と閲覧

主催者のログイン、ユーザー・SAML 設定の変更、機能フラグ、競技者アカウントの登録・検証・削除、イベントの作成・更新、環境の起動・停止・削除を記録します。記録する値は、処理 ID、日時、操作名、対象の ID、結果、操作時点の主催者 ID・ロール・認証方式です。認証に失敗した要求は、利用者が入力した名前を保存せず、匿名の試行として記録します。

パスワード、ホスト鍵、チーム鍵、トークン、SAML 応答、NameID、AWS 資格情報、リクエスト本文、IP アドレス、任意の追加フィールドは保存しません。

Admin だけが「監査ログ」画面と CSV 出力を利用できます。Operator と Viewer は閲覧できません。記録を停止した後も、保存済みのレコードは Admin が閲覧・出力できます。記録の開始と停止も、それぞれの設定変更と同じトランザクションで保存します。

停止中の操作を後から補充することはありません。記録がないことは、操作がなかった証明にはなりません。

## 保存失敗と外部処理

ユーザーやイベントの設定変更では、監査の保存に失敗すると、その変更もロールバックしてエラーを返します。環境操作は、受理記録を保存してから実行を始めます。

すでに受理した環境操作は、監査の保存に失敗しても実行結果を通常のジョブ記録へ保存します。セッションの失効や、再検証に失敗した競技者アカウントの利用停止も、監査の障害では取り消しません。欠落した監査記録の件数を管理画面に表示し、外部処理の結果はジョブの状態で確認できます。要求・結果・削除結果は同じ処理 ID で関連付けます。再起動時には、未確定の記録を残してから復旧結果を追加します。

データベース全体が書き込めない場合、欠落数の永続化も保証できません。その場合は、現在のプロセスで保持している件数であることを画面に表示します。

## 保持と出力

直近 30 日、最大 10,000 件を保持します。記録の追加・一覧取得・出力時に上限を超えた古い記録を削除します。画面の日時・実行者 ID・操作名のフィルターは完全一致で扱います。日時だけは指定範囲を検索します。

CSV は一度に最大 5,000 件です。検索結果が上限を超えるとエラーを返します。途中までの出力を成功とは扱わないため、期間や実行者を絞って再実行してください。

監査記録は host のデータベースと同じバックアップ対象です。ホストやデータベースを管理する人による改変を防ぐ外部保管機能は含みません。

## 開発時の確認

`bun test scripts/local-host/tests/audit-log.test.ts scripts/local-host/tests/audit-http.test.ts` は、実 HTTP・SQLite の経路で権限、記録の停止、秘密情報の除外、保存障害、再起動後の関連付けを確認します。

`bun run test:host:audit` は、ビルド済み管理画面で有効化、操作履歴、CSV 出力、欠落表示、停止後の閲覧、Viewer の拒否を確認します。試験は一時データベースと専用の問題エンジンを使います。
