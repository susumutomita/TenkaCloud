天下クラウド株式会社 — 世界観設定

クラウドはわかる。 でもプロダクションはまた別ものだ。 — 加藤さん (前任 SRE)

あらすじ

東京都内、 中堅の SaaS スタートアップ 天下クラウド株式会社。 「すべての企業に最高のクラウドを」 をミッションに掲げ、 マルチクラウドでの自動デプロイ プラットフォームを提供している (= つまりこの TenkaCloud 自体)。

ところがある日、 唯一の SRE であった 加藤さん が突然 退職した。 退職理由は 「もう少し近場のクラウドで働きたい」 という曖昧なもの。 引継ぎ書らしき ものは Notion に断片的に残されているが、 production 環境はあちこちに罠が仕掛けられた まま、 SSM Parameter Store に意味不明な文字列が残り、 IAM Role には 「あとで消す」 と コメントだけ書かれた policy がぶら下がっている。

そして あなたは、 加藤さんの後任として 入社初日に PC を渡された。 「とりあえず production に 触ってみて」 と CTO は言って、 そのまま会議に消えた。

主要人物

あなた (= 新人 SRE)

天下クラウド入社初日。 前職は別の業種で、 AWS は触ったことがある程度。 加藤さんが 残した「課題」 を 1 つずつ解いていく。 失敗してもいい (= ステージング環境)、 ただし 総当たりはダメ。

加藤さん (= 前任 SRE)

生年月日不詳、 出身大学不詳、 趣味は terraform apply --auto-approve。 口癖は 「あとで直す」。 退職前に書いたコミットメッセージはすべて 「fix」 の 1 単語。 今は連絡がつかない。

佐々木 CTO

天下クラウド創業者。 元 Web エンジニア。 「とりあえず動けばいい」 派。 入社初日のあなたに 本番 AWS アカウントの IAM Role を渡してから、 すぐ営業に行ってしまった。

「ユニコーン株式会社」 (= 顧客)

天下クラウドのお客様。 ある日突然 「サービスが落ちた」 「攻撃を受けた」 と連絡してくる。 contract には SLA 99.9% と書いてある。

競技ジャンル

カテゴリ位置づけ例
Challenge 加藤さんが残した 1 個の課題を、 1 人で解く。 flag (= AWS リソースの値) を Portal に提出して点数を取る。 hello-world, ssm-parameter-quest, iam-policy-mystery
Battle 顧客 「ユニコーン株式会社」 の本番障害を、 複数チームで同時に直す。 一定時間ごとに監視 endpoint を probe して、 生きている時間に応じて点数を稼ぐ。 hello-world-battle, microservice-migration-battle, security-battle-royale

世界観 (= tone of voice) ガイドライン

TenkaCloud で問題を作るときの language tone:

  • 軽い皮肉: 加藤さんは多少 lazy で 「あとで消す」 「動けば OK」 派。 問題の background story には そんな雰囲気を残す。
  • 実務的: 突飛なファンタジー要素は入れない (= 「魔法の SSM Parameter」 ではなく 「加藤さんが残した SSM Parameter」)。
  • 競技者を主人公に: 「あなたは新人 SRE として……」 から始める。 「This problem」 ではなく 「あなたが今 触っているこの環境では」。
  • 非英語圏も想定: 第一言語は日本語、 metadata.i18n で英語訳も提供する (= Issue #583 Phase 5 で確立済の i18n 機構を使う)。

問題作成者向け 物語チェックリスト

新しい問題を problems/<category>/<id>/metadata.json に追加するとき:

  1. shortDescription: 1 行で 「何をする」 を競技者目線で書く。 例: 「加藤さんが SSM Parameter に残した謎の挨拶を読んで Portal に貼り付ける。」
  2. description: 数段落で背景 (= なぜこの問題が必要になったか) + 競技者の ミッション (= 何を達成すれば +pt) を書く。 加藤さんの台詞や Slack 履歴の引用を 1 つ入れる と tone が引き立つ。
  3. learningGoals: ストーリーではなく実務スキルの箇条書き。 ここは 普通に dry でよい (= 「SSM Parameter Store を AWS Console / CLI で読む経験」)。
  4. hints (任意): 加藤さんがコメント残してくれてたら親切、 という体で。 penalty は問題の難易度に合わせて (= 簡単な hint は -5pt、 致命的な hint は -30pt 等)。

参考: AWS の競技 program との関係

本世界観は AWS 公式の narrative-driven cloud competition program (年次の "GameDay" 系 イベント) から着想を得ている。 ただし、 AWS 公式が用いる fictional company 名 / character 名 (= 当該 program 固有の branding) は流用せず、 TenkaCloud 独自の lore (天下一武道会 / 天龍 系) を用意している。 OSS / 商用配布での IP 線引きとして、 これを harness rule (no-aws-trademark-fictions) で機械的に enforce する。

TenkaCloud は OSS で問題を追加 / 修正できるため、 lore も community contribution と して育てていける形にしている。

新キャラ / 新会社設定の追加提案は GitHub Issue で lore ラベルを付けて提案して ください。
