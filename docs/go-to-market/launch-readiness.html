Launch Readiness Checklist — Phase Gates for OSS Reveal, Paid Pilot, and Enterprise Annual

Tracking issue: #1370
Parent epic: #1336 (Commercial launch readiness)
Status: Living document
Owner: Maintainer team
Update cadence: Before each Phase decision; recorded in §8 Decision log

TenkaCloud should not wait for every future feature before public reveal or first commercial pilot. This document encodes enough, not perfect — the explicit gates the maintainer team uses to decide go / no-go for the three milestone launches.

Done — shipped, evidence linked Gap — required for this phase, not yet ready Roadmap — tracked, deferred past this phase Not required for this phase

How to use this document

For each phase, walk every Required row. The phase is go when every required row is Done and no Gap blocks remain. Roadmap items are tracked but explicitly out-of-scope for the gate — they do not block. Not required items are listed in each phase verbatim from #1370 so the boundary is auditable; they are not silently dropped.

This document captures status at the moment a decision is made. To re-decide, walk every row again. Record the go / no-go in §8 Decision log; do not silently re-grade rows here without an accompanying log entry.

5. Known limitations to say out loud

Customer- and community-safe phrasing. State them in pitch decks, sales calls, and on the LP. Surprising a buyer with these mid-engagement is worse than leading with them.

LimitationPublic-safe phrasing
No SOC2 certification yet "TenkaCloud implements SOC2-oriented controls — immutable audit pipeline, configurable retention, exportable evidence. Formal SOC2 attestation is on the roadmap; it is not in hand today. For Annual Arena buyers under a procurement SOC2 requirement, we work through their security-questionnaire process with the controls listed in docs/security/HARDENING-CHECKLIST.html."
No multi-cloud runtime "TenkaCloud problems run on AWS. The plugin model (ADR-012) and provider-specific runtime decision (ADR-023) leave room for additional providers later, but the supported path today is AWS only."
No universal cloud problem compiler "Each problem is a single-page CloudFormation template plus optional portal slot. There is no abstraction layer that compiles one problem definition into multiple providers. Authors who want a problem on a non-AWS provider write that provider's template — the platform itself is provider-agnostic at the plugin boundary."
Web3 / community voting is not implemented "ADR-024 describes a future community voting / problem registry layer. It is not built today. Problem curation is currently maintainer-led through the TenkaCloudChallenge repo."
No full self-service SaaS "Tenant onboarding for paid engagements is maintainer-operated today. The infra to support self-service is present (SBT control plane, per-tenant pipeline, application plane), but the public signup / billing path is not. Hosted Event pilots are run hands-on with the maintainer team."
