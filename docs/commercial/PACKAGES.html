TenkaCloud — Commercial Packages

What you can buy, what is in scope, what is not, and how the work is delivered. The platform itself stays OSS (Apache 2.0). Paid offerings fund facilitation, custom problems, and program-level support.

The four offerings at a glance

TenkaCloud's commercial path is productized services, not open-ended consulting. Three offerings sit inside the productized core. A fourth — CCoE Enablement — is intentionally kept as a separate advisory add-on so it does not dilute the productized core.

Productized service
Hosted Event

A 1-3 day event, run by us, on the public problem catalog. Branded portal, live facilitation, post-event report. One-shot, fixed scope.

Advisory only · not bundled
CCoE Enablement (add-on)

Monthly retainer for CCoE operating model / training roadmap / problem catalog roadmap. Sold separately from event delivery so it does not turn the productized services into open-ended consulting.

Jump to CCoE Enablement ↓

Productized vs. consulting. Hosted Event, Annual Arena, and Custom Problem each have a fixed shape: known inputs, known deliverables, known exclusions. If the conversation drifts toward "we also want you to design our internal change-management process," that is CCoE Enablement, not these three. Keeping the line sharp is what lets a small team deliver predictably.

How they compose

The packages are independent but designed to compose cleanly:

  • Hosted Event is the entry-level paid offer. Many engagements start here, validate the experience, then graduate.
  • Annual Arena = "Hosted Event × N, with a private catalog and a KPI dashboard wrapped around it." It is not just a volume discount; it adds program-level deliverables.
  • Custom Problem can be sold standalone or bundled into Annual Arena as the private catalog. Inside Annual Arena it is an optional line item, not a default inclusion.
  • CCoE Enablement is sold to buyers who want strategy work in addition to events. It is never bundled into the three offerings above; if a buyer wants both, the contract has two line items.

1 · Hosted Event Productized service

A 1-3 day cloud drill, run by us, on your AWS account, using the public OSS problem catalog. The most direct paid entry point — a buyer can purchase exactly one of these and get a complete, credible event.

Target buyer
CCoE leads, platform / SRE / security teams running a one-off internal drill; cloud communities, JAWS-UG chapters, schools, bootcamps; conference organizers who want a hands-on track.
Outcome
One credible event end-to-end: a branded participant portal, isolated AWS environments per team, live facilitation, real scoring, a post-event report that the buyer can show to their leadership.
Pricing structure
Per-event fixed fee + optional per-participant uplift above a baseline team count. TBD pricing tier (public starting price summarized on landing page).
Effort budget
~5-8 person-days per engagement (design + setup + run + report).
Delivery model
Remote-first. On-site facilitation possible as a separately quoted line item (travel + day rate). All event tooling runs on the buyer's AWS account via the standard OSS deploy path (Lite or SaaS mode).

Deliverables (what is included)

ItemDescription
Event design sessionOne 60-90 minute kick-off. We align on participant level, learning goals, length, and the problem mix from the public OSS catalog. Output: an event design memo.

Dry runOne full rehearsal with the buyer's facilitator and 1-2 internal testers, 1-2 weeks before the event. We fix anything that surfaces.
Live facilitationFor the duration of the event we are on-call for: kick-off run-through, team onboarding, hints, scoring tie-breaks, attack injection (Battle Red Team role where applicable).
Result summaryScoring history, per-team progress, attack timeline (Battle) or solve timeline (Challenge), exported as a PDF report. One PDF per event.
Post-event issue listTriaged list of problem-bugs / UX papercuts / feature requests we encountered, opened as upstream OSS issues where applicable.

Not included

ItemWhy it is excluded
New problem authoringIf the buyer needs a problem that does not exist in the public OSS catalog, that is Custom Problem scope — sold separately.
Buyer's AWS accountThe buyer brings their own AWS account. If we need to provide one, that is quoted separately (AWS bill pass-through + administrative overhead).
Production-data scenariosWe never integrate with production data or production accounts. Scenarios are synthesized.
SOC 2 / compliance artifactsThe OSS platform's security posture is documented (cross-account AssumeRole + ExternalId, audit logging, isolation invariants). Producing buyer-specific compliance artifacts (custom DPA, SIG questionnaire, etc.) is a paid line item.

Post-event ongoing operationThe platform is torn down after the event (one teardown command). If the buyer wants the platform to keep running, see Annual Arena.

2 · Annual Arena Productized service

A 12-month engagement to run 4-6 operated events for one organization, build a growing private problem catalog, and report on it with HR / training KPIs. The right shape for an enterprise CCoE program or a long-running platform-enablement track.

Target buyer
Enterprise CCoE / cloud enablement programs; new-grad onboarding programs that span a fiscal year; org-wide internalization (内製化) initiatives where the buyer needs repeat events on a budgetable annual line.
Outcome
A year-long, measurable cloud-capability program: 4-6 events that progress through difficulty levels, a private problem catalog that grows with the buyer's reality, and a KPI dashboard the buyer's HR / L&D team can present to leadership.
Pricing structure
Annual base fee (covers program design, dashboard hosting, baseline support hours) + per-event variable (each operated event priced by size). TBD pricing tier.
Effort budget
~30-40 person-days over 12 months (= ~6 person-days per event × 5 events + ~5 person-days program overhead).
Delivery model
Year-long retainer. Quarterly cadence reviews. Per-event delivery follows the Hosted Event playbook but uses the buyer's private catalog. Optional Custom Problem line items grow that private catalog over time.

Deliverables (what is included)

ItemDescription
Program designAn annual learning path: which audiences (new grad, mid-level, platform team), which cadences (quarterly, by cohort), which difficulty progression. One program design memo.
4-6 operated eventsEach event delivered as a Hosted Event variant — design / setup / dry run / live / report. Buyer chooses dates within the contract year.
Private problem catalogA buyer-owned catalog (forked from the public OSS catalog, or stood up empty). The buyer owns the IP of any custom problems in it. We curate it; we do not own it.
KPI dashboardA view that surfaces per-event metrics in a form HR / L&D can use: participation rate, completion rate, score progression by cohort, problem-coverage of the catalog over the year. Refreshed after each event.
Problem backlog managementA rolling list of candidate problems (suggested by us, requested by the buyer). Two of these can be promoted to Custom Problem line items per year at no additional design fee (= just the per-problem build cost).
Quarterly improvement roadmapOnce per quarter, a 30-minute review with the buyer's program owner: what worked, what did not, what to adjust for the next cohort.

Not included

ItemWhy it is excluded
Unlimited Custom ProblemsCustom Problem authoring is per-problem priced (see below). Annual Arena waives the design fee for two Custom Problems per year; build cost still applies. Additional Custom Problems are billed as line items.
24x7 production-grade SLAEvents are scheduled, not always-on. Between events the platform sits idle (= no SLA, near-zero cost).
Internal change-management / org transformation workThat is CCoE Enablement — sold separately. Annual Arena delivers events and reports; it does not redesign the buyer's internal training operating model.
Hiring assessments / certification authorityThe KPI dashboard reports participation and scores. It is not a hiring tool, a certification body, or an HR system of record.
Multi-cloud (Azure / GCP)The platform is AWS-first by design. Other clouds may arrive later (see #1266) but are not in current scope.
The buyer's AWS billThe buyer pays AWS directly. Our pricing covers our labor, not infrastructure pass-through.

3 · Custom Problem Productized service

A single, named problem authored to match a buyer's actual stack or past incident. Delivered as a self-contained problem directory (metadata.json + template.yaml + optional portal). The buyer owns the IP unless they choose to contribute it to the public OSS catalog.

Target buyer
Companies with a specific training gap (a service their teams keep mis-configuring), a recurring incident pattern they want to drill, or a stack the public OSS catalog does not yet exercise.
Outcome
One ready-to-run problem in the buyer's private catalog (or, by the buyer's choice, contributed to the public catalog), with scoring rule, dry-run verification, and facilitator notes.
Pricing structure
Per-problem fixed price, tiered by complexity (intro / intermediate / advanced — based on the 5-kind decision tree). TBD pricing tier.
Effort budget
~8-15 person-days per problem (scenario design + implementation + scoring + dry-run + facilitator notes).
Delivery model
Async-first. One 60-minute scenario interview, then implementation in our worktree, then a dry-run review with the buyer before sign-off. Delivered as a PR (catalog repo) or a zip (private catalog).

Deliverables (what is included)

ItemDescription
Scenario designA 60-minute scenario interview with the buyer's SME. We come back with a written scenario brief (audience, stack, success criteria, scoring kind from the 5-kind decision tree).
Problem implementationmetadata.json + template.yaml + optional portal React component, written against the public OSS schema (SCHEMA.json), validated with make validate-problems.
Scoring designChoice of the right scoring kind (flag / uptime-flat / uptime-multi / phased-polling / attack-detection) and the corresponding parameters in metadata.json.
Dry-run verificationDeployed end-to-end into a test AWS account, played through, scoring observed. Bugs fixed before sign-off.
Facilitator notesA short markdown brief: setup time, common participant traps, hint progression, sample solutions, teardown verification.
IP assignmentThe buyer can choose: keep the problem private (we deliver as a zip with a buyer-owned IP assignment), or contribute it back to the public OSS catalog under Apache 2.0.

Not included

Production access — never. A Custom Problem is a sanitized scenario, not a replica of the buyer's production system. We do not connect to production accounts, ingest production data, or replicate production credentials. If the buyer needs the realism of production, that is a separate security and compliance conversation, not a Custom Problem.
ItemWhy it is excluded
Production data, secrets, or credentialsThe scenario is synthesized. Buyer-provided context is used only to inspire the design.
Live production access of any kindNo read access, no AssumeRole, no log shipping. The dry-run uses our test AWS account or the buyer's pre-production account.
Multi-problem learning pathsEach Custom Problem is one problem. A learning path made of N custom problems is N Custom Problem line items.
Ongoing maintenanceThe delivered problem is a snapshot. If the buyer's stack evolves and the problem needs to evolve with it, that is a revision line item (typically 25-50% of the original fee).
Compliance-grade audit trailsThe scenario design interview is recorded only with explicit consent. We do not produce certified chain-of-custody artifacts.
Operating the problem at eventsThat is Hosted Event or Annual Arena. Buying just a Custom Problem gives the buyer the asset; running an event with it is a separate engagement.

4 · CCoE Enablement Advisory · sold separately

An advisory retainer for buyers who need help with the operating model around their cloud enablement, not just events. Explicitly not bundled into the three productized services above so that those stay productized.

Why this is a separate package. CCoE consulting is open-ended by nature: scope grows with the buyer's internal politics, the work bills hourly, and a small team cannot deliver it predictably alongside event operations. Keeping it as an opt-in retainer means Hosted Event / Annual Arena / Custom Problem stay productized — and a buyer who wants both signs two contracts, not one blurred one.
Target buyer
Companies that need strategy, process, or change-management support to make their CCoE program land — not just hands-on training events. Often Annual Arena buyers who realize mid-year that they also need org-level work.
Outcome
A documented CCoE operating model, a training roadmap, a catalog roadmap, and an internal adoption strategy that the buyer's CCoE lead can present internally.
Pricing structure
Monthly retainer. Engagement length default 3-6 months, renewable. TBD pricing tier.
Effort budget
~4-6 person-days per month (weekly working session + async deliverables).
Delivery model
Weekly 60-minute sync. Monthly written deliverable. Async Q&A between syncs. No bundling with event delivery — if the buyer also wants events, that is a separate Hosted Event / Annual Arena line item.

Deliverables (what is included)

  • CCoE operating model review — How the buyer's current CCoE is structured, where the gaps are, what to keep and what to change.
  • Training roadmap — 12-month plan for capability building. Audience segmentation, content cadence, ownership.
  • Problem catalog roadmap — Which problems the buyer should invest in over the year (commission as Custom Problems, request as public catalog contributions, or skip).
  • Internal adoption strategy — How to land the program inside the buyer's org. Stakeholder map, communication plan, success criteria.

Not included

  • Event delivery. Running events is Hosted Event / Annual Arena. Buy those separately.
  • Custom problem authoring. Authoring is Custom Problem. Buy that separately.
  • Headcount / hiring decisions. We recommend operating shapes; we do not run the buyer's recruiting pipeline.
  • Internal political work. We provide artifacts and recommendations; landing them internally is the buyer's responsibility.

How to engage

  1. Decide which package fits. Use the Sales Playbook qualifying questions if unsure.
  2. Request a quote. Via the landing page contact form or GitHub Discussions.
  3. Discovery call. 30-60 minutes to confirm scope, dates, and any exclusions that need calling out.
  4. Statement of work. A one-page SoW (one of the templates linked from the playbook) for sign-off.
  5. Kick-off. The package timeline starts.
