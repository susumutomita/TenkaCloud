TenkaCloud Design System

The visual quality bar for a commercial-grade SaaS competition platform. Built on top of Cloudscape Design System; this document records the TenkaCloud-specific extensions, status taxonomy, and the four screen-state patterns (loading / empty / error / success) that every page must implement.

Issue #1366 · Builds on #1362 (formatters as source of truth) and #1349 (event-day portal polish).

1. Design principles

  1. Enterprise credible, not toy-like. Start from raw Cloudscape — only customize when the out-of-the-box version actively reduces buyer trust.
  2. Event energy where it matters. Participant Portal and live status surfaces should feel alive (CountdownTimer, NextActionHero, score deltas in real time).
  3. Clear next action. Every page must answer: what should the user do next? Empty states without a primary action are forbidden.
  4. Stateful polish. Loading, empty, success, failure, and disabled states must all be designed. Whichever state a user lands on, the page must look like it was finished on purpose.
  5. Screenshot-worthy. Pages on the landing-page screenshot list must hold up under marketing crop without retouching.

2. Typography

TenkaCloud inherits Cloudscape's typography tokens. Do not override font-family globally — Cloudscape's stack is tuned for cross-OS rendering and a-11y. Use Box / Header variants instead of raw HTML tags, so the system reflows under density="compact" and visualRefresh.

Rule: don't use raw <h1> / <p> tags. Cloudscape's Header and Box bring the focus ring, color, density, and a-11y semantics for free.

3. Spacing scale

Use SpaceBetween + Cloudscape awsui-spacing-* tokens. We never write raw margin / padding in React components. The five usable sizes are:

xxs4 pxinside a badge / between a label and its value xs8 pxbetween dense list rows s12 pxbetween table rows / between key-value pairs m16 pxbetween paragraphs inside a Container l20 pxbetween top-level page sections (default for SpaceBetween) xl24 pxbetween major dashboards xxl32 pxbetween fully separate concerns on the same route
Default for page-level layout: <SpaceBetween size="l">. Inside a Container, drop to size="m".

5. Status badge system

Status enums never display as raw strings. They are routed through pure formatters in apps/<spa>/src/lib/format.ts (the canonical source — established in #1362) and rendered as Cloudscape <Badge> with the matching color.

6. Problem card pattern

Each problem on the participant portal is rendered as a Cloudscape Container with a Header variant="h2". The header has three slots: problem title · status badge · score chip. Inside the container: a short description, then the primary action (Open / Submit flag).

8. Empty state pattern <EmptyState />

Slots, in order: icon (decorative; muted) → headline (one short sentence) → body (1–2 sentences explaining how to fill this list) → primary action (a Cloudscape Button that creates the missing thing). The component lives in apps/<spa>/src/components/design-system/EmptyState.tsx.

Forbidden: an empty Box with just "no data". Every empty state must have a headline + body + actionable next step (or an explicit "you don't have permission" message).

9. Error state pattern <ErrorState />

Backend errors are converted through friendly-error mappers (introduced in #1349 / #665). The ErrorState component wraps Cloudscape Alert type="error" and exposes title, hint, possible causes list, and an optional retry action. Raw JSON / stack traces are never shown to end users.

API shape 
interface ErrorStateProps {
  title: string;
  hint?: string;
  possibleCauses?: readonly string[];
  retry?: { label: string; onClick: () => void };
  dismiss?: () => void;
}

When the error is from an ApiError, call toFriendlyError(err) first, then pass { ...friendly, retry, dismiss } to the component.

10. Loading / skeleton pattern <LoadingState />

For requests under ~300 ms: show a Cloudscape <Spinner /> with an inline label. For requests over ~300 ms: render a section-level skeleton (greyed-out Containers in the right layout). For polling refreshes: keep the previous data visible and show a small inline indicator near the manual-refresh button.

API shape 
interface LoadingStateProps {
  label?: string;     // visible next to the spinner; default "Loading..."
  textAlign?: "left" | "center";
  padding?: "s" | "m" | "l"; // Cloudscape Box padding token
}
Forbidden: blank screen with no spinner. Forbidden: spinner without any label when the wait can exceed 1 s. Buyers read a blank screen as "broken".

12. Enforcement

  • Each SPA mirrors src/components/design-system/{EmptyState,ErrorState,LoadingState,StatusBadge}.tsx — same 3-SPA copy-paste convention as lib/format.ts (sharing across workspaces is a bigger refactor; see #1362).
  • Pages that show a list must use <EmptyState> when the list is empty.
  • Pages that fetch data must use <LoadingState> on the initial load and <ErrorState> on fetch failure.
  • Status values rendered as a chip use <StatusBadge> with the canonical color map.
  • Unit tests in apps/<spa>/test/components/design-system/ lock down the public surface so a regression on the design system shows up in CI.

13. Logo & brand mark

The TenkaCloud logo is the Summit mark — the top stroke of 天 (heaven) plus a ridge rising to the peak (天下 = reaching the top). It is monochrome and geometric so it survives down to 16 px and reads as a trademark. Alternates ascend and cloudpeak exist for motion/variant use. Full guidelines (lockups, clearspace, do/don't): logo.html.

Unlike the status colors above (which are Cloudscape's functional tokens), the brand layer is a separate palette consumed wherever color is set outside Cloudscape (logo, favicon, landing). Its source of truth is the @tenkacloud/web-kit brand kit; the same values are published as --tc-* CSS custom properties in packages/web-kit/src/brand/brand.css.
