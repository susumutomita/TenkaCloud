# 参加リンクから準備済みチームを受け取る

現在の自己登録は、配置済みで準備が整ったチームを割り当てる機能です。登録時に
チーム、AWS アカウント、問題環境を作成しません。デフォルトでは OFF で、Admin が host の
feature flag と大会の Teams 設定を管理します。

## 運営が準備するもの

`make local` で起動し、大会とチームを作成して必要な問題環境を配置します。
自己登録を有効にし、未配布で準備済みのチームと受付期限を選び、参加リンクを保存します。
リンクは安全に配布します。再発行すると旧リンクは無効になりますが、既存の割り当ては残ります。

## 参加者の操作

リンクを開き、チームを受け取ります。ブラウザは受付票を保存し、再試行や応答消失後も
同じチームを取得できます。準備完了後は通常の参加者ポータルでチームキーを使います。
キーと受付票は共有しないでください。

## 失効と保存

受付終了や feature flag の OFF は新規割り当てを止めます。既存の割り当てや通常の
チーム参加権をリセットしません。大会の終了・期限切れは受付票での取得を止めます。
チームキーを交換すると旧受付票は失効し、新しいキーは返しません。`make down` は
自己登録の状態も保持します。

[host の自己登録契約](../host-participant-registration.md)に、準備状態、原子的な
割り当て、受付票を説明しています。準備状態は保存記録に基づき、その場でのクラウド
健康確認ではありません。実環境や全 Docker・terminal の動作は別に検証します。

## 旧版の経路

[固定した旧版の資料](https://github.com/susumutomita/TenkaCloud/blob/825415fcda5075ad723daf9e4514eac47d7b8bb9/docs/operations/participant-self-registration.md)は
異なるクラウド配置の仕組みです。現在の契約ではなく、既存の登録は自動移行されません。
