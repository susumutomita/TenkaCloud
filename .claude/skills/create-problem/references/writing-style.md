# 問題コピーの言い回し (writing style)

競技者に見せるコピーの正統な声 (voice)。本家 **AWS GameDay** の作法と、TenkaCloud の house style を統合した正本。

**適用対象（競技者が読む）**: `name` / `shortDescription` / `instructions` / `hints`
**適用外**: `description` は作者向け（採点ルール・hardened state・ネタバレ）。技術的な素の文でよい。

新規問題は `/create-problem` でこのファイルに沿って書く。既存問題を直すときもこの基準で判定する。

---

## 1. 声を 1 行で

> 君は天下クラウド株式会社のエンジニア。ある朝、引き継いだシステムが壊れる。CTO が短く指示する。君が直す。

競技者を物語の主人公（二人称「君 / あなた」）に置き、状況に**放り込む**。説明しない、体験させる。
本家 AWS GameDay も同じ作法 ── 架空企業に新入りとして雇われ、二人称で「やること」を渡される。

---

## 2. 世界観（固定設定）

| 要素 | 設定 |
| --- | --- |
| 会社 | **天下クラウド株式会社**（明らかに架空の自社風の舞台。実企業ではない） |
| 立場 | 君 / あなた = 競技者本人。新人〜異動直後のエンジニアが多い |
| 上司 / 運営 | **役職で呼ぶ**: CTO / 運営 / セキュリティ担当 など。短く・具体的で・絵が浮かぶ命令を出す。`CTO 曰く: 「…」` |
| 前任者 | 引き継ぎ元。**役割（前任者 / 前の担当）で呼び、blameless に**。異動・退職などで居ないだけ |
| 時間軸 | **cold-open**。「ある月曜の朝」「入社初日」「ネットワーク班 4 日目」 |

### 絶対ルール — 実在の誰かが不快にならないこと（最優先）

- **個人名（苗字・名前）を使わない。** 「加藤さん」「佐々木 CTO」のような苗字付きキャラは禁止。佐々木も加藤も世の中に実在する。役職・役割（CTO / 運営 / 前任者）だけで問題は十分成立する。
- **実在の人物・組織・実企業をモデルにしない。** 特定の会社・部署・個人を想起させる設定にしない。
- **前任者を「無能 / 怠慢 / トラブルメーカー」として描かない。** ドラマは**人ではなくシステム・状況**から作る。「引き継いだシステムが壊れている」は OK、「前任者が無能だったから壊れた」は NG。前任者が居ない理由（異動・退職）に悪意や評価を込めない。
- **AWS GameDay の架空企業名を流用しない。** AWS 公式 training の branding なので IP リスクになる。舞台は自社の **天下クラウド株式会社** を使う（harness rule `no-aws-trademark-fictions` が該当語を検出する）。

---

## 3. フィールド別の書き方

### `name`（≤80 字）
素直な問題名。凝らない。例: `Security Battle Royale` / `WAF Classic 供養`。

### `shortDescription`（カード表示。1〜数段落）
**cold-open のシナリオ導入**。型:

1. **時・場・立場** ── 「天下クラウド株式会社、ある月曜の朝。」
2. **状況** ── 引き継いだシステムが、今おかしい。構成は名詞で具体的に（`mysql + Flask + nginx を EC2 1 台に同居`）。人のせいにしない。
3. **役職の一言** ── `CTO 曰く: 「攻撃が来てる。落とすな、守れ、全部直すな」`
4. **君の仕事を 1 文** ── 「君の仕事は frontend / api を 200 で返し続けること」

- 採点の数字・hardened state・正解はここに書かない（→ `description`）。
- 「本問題では〜を学びます」「〜への理解を深めましょう」は**禁止**（→ §4）。

### `instructions`（競技者向け手順）
見出しは 3 つ: `## はじめに` / `## 最初の一手` / `## ゴール`。
「最初の一手」は**番号付きで「今すぐ何を押す/打つか」**。本家の *Your Mission* / *Where things are* / 番号手順に対応。

### `hints`（progressive）
段階的に具体化。1 個目は方向だけ、後半ほど答えに近い。命令形・短文。
例: `relay から app の :443 に curl して、 まず TCP が通るか確認`。

---

## 4. AI 臭さ（禁止）── before → after

「読みづらい」の正体はこれ。**抽象的な前置き・自己解説・空虚な形容**を消し、シナリオと命令に置き換える。

❌ before（AI 臭）:
> セキュリティの重要性が増す昨今、本問題では AWS WAF の移行について実践的に学ぶことができます。堅牢かつ包括的な防御を構築し、シームレスな保護を実現していきましょう。

✅ after（house style）:
> 天下クラウドの公開プロフィール API は、長らく WAF Classic の 3 ルールで守られてきた ── が、WAF Classic は終了する。CTO 曰く: 「移行しろ。穴は開けるな」。

### 禁止・要注意の語句

| 種別 | 避ける | 代わりに |
| --- | --- | --- |
| 個人名 | 苗字付きキャラ（〇〇さん / 〇〇 CTO） | 役職・役割（CTO / 運営 / 前任者） |
| 人を悪役化 | 前任者が無能で / 〇〇のせいで | システム・状況を主語にする |
| 自己解説の枠組み | 本問題では〜 / 〜を学びます・習得します / 〜への理解を深める | シナリオに放り込む。学びは結果であって前口上ではない |
| 時事の前置き | 昨今 / 近年 / 〜が増す中 / 〜が重要です | 削除。状況そのものを書く |
| 空虚な形容 | 堅牢 / 包括的 / 強力 / 最先端 / シームレス / 柔軟 | 具体名詞・具体動作に置換 |
| バズ動詞 | 活用する / 実現する / 担保する / 〜していきましょう | 直す / 塞ぐ / 返す / 確認する など実動作 |
| 締めの定型 | ぜひ挑戦してみてください / 頑張りましょう | 締めない。最後は「君の仕事は〜」で終える |
| EN 版 | leverage / utilize / seamless / robust / comprehensive / cutting-edge / "In today's…" / "In this challenge you will learn" / delve / facilitate | drop you into the scene; second person + imperative |

## 5. 見出し・締めの語彙（再利用）

| 用途 | 日本語 | 本家 EN |
| --- | --- | --- |
| 導入 | はじめに / 状況 | Welcome to the battle / Welcome, New Hires |
| 任務 | 最初の一手 / 君の仕事 | Your Mission / Where things are |
| 注意 | 注意 / 落とし穴 | Things to watch out for |
| 助言 | コツ | Tips and tricks |
| 完了 | （締めない or 一言） | Wonderful job! / you are good to go! |

`difficulty` / `estimatedTime` は本家の `Difficulty: 100 level` / `Average completion time: 5 minutes` に対応。誇張しない。

---

## 6. i18n

`ja` と `en` の両方を**同じ温度**で書く。en は直訳でなく、本家 GameDay の声（二人称・命令形・簡潔）で書き直す。
